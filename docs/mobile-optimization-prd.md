# AIPP 移动端改造 PRD

> 版本：v2.1<br>
> 更新日期：2026-11-02<br>
> 状态：需求草案，作为后续移动端开发、评审和验收依据。<br>
> 目标平台：Android 手机与平板；iOS 不在本期范围。

本文依据当前仓库代码、AGENTS-mobile.md 和移动功能盘点编写。代码中已经存在的链路不等于已经通过 Android 构建或真机验收；发布状态必须以设备验证记录为准。

v2.1 追加 MOB-14 至 MOB-19，来源为 2026-11-02 移动端「应该有但目前没有」缺口盘点，已登记到 leaderai AIPP 项目（需求 #250–#258）。本次同时把原 MOB-13 中的系统分享接收、通知跳转从 M3 前移到 M2，并把后台保活拆成「前台持锁」与「常驻前台服务」两档。

## 1. 产品目标

将 AIPP Android 端建设为可以独立完成以下闭环的客户端：

1. 配置模型和助手；
2. 发起、继续和管理 AI 对话；
3. 导入图片或文档；
4. 使用已兼容的网络工具和轻量内置工具；
5. 阅读、保存和分享结果；
6. 查看同步状态、任务状态和审批请求。

移动端直接支持网络模型和已适配的网络工具。依赖电脑 CLI、桌面操作系统、开发环境或本地进程的能力，不作为当前移动本地执行能力承诺。未来通过电脑执行的需求必须由独立 Host Bridge 项目实现。

### 1.1 首个移动版本的范围

**M1 必须完成**

- 单 WebView 移动导航和返回栈；
- 对话、会话列表、搜索、流式回复、取消、编辑和重生成的触控闭环；
- 模型、助手、基础 HTTP MCP 配置；
- 图片和文档附件的移动文件链路；
- Markdown、Word、PNG 的保存和系统分享；
- 同步状态、前后台恢复和中断状态展示；
- 离线状态区分与断网失败可解释（MOB-14）；
- 移动端不支持能力的统一隐藏和明确错误。

**M2 交付**

- 静态制品预览和收藏；
- Skills 管理；
- 纯前端或网络型插件；
- Butler 任务台、定时任务管理和前台飞书能力，含任务的移动端新建与编辑（MOB-18）；
- 会话详情面板（MOB-16）；
- 回复期保活、中断通知与通知点击回到会话（MOB-15）；
- 接收系统分享、拍照添加附件（MOB-17）；
- 会话列表手势与长对话轮次跳转（MOB-19）。

**M3 或独立项目**

- 移动搜索和 URL 抓取；
- PDF 生成、图片剪贴板；
- React/Vue 浏览器内预览；
- deep link、移动更新；
- 可靠后台调度、常驻前台服务、长期在线服务、Host Bridge 远程执行、本地脚本运行时、iOS。

### 1.2 非目标

- 不在本期将 Codex、Claude Code、ACP、Python、Bun 或外部 stdio MCP 搬到 Android 本地运行。
- 不把数据同步解释为远程执行；不通过同步状态模拟电脑上的实时进程或审批。
- 不复刻桌面托盘、全局快捷键、桌面多窗口、窗口置顶和跨应用选词。
- 不保证应用退出或进程被系统回收后定时任务、Butler、飞书机器人继续运行。
- 不新增模型、provider、会话、工具或执行通道的静默回退。

## 2. 当前代码基线

以下基线以 2026-10-28 代码为准，开发开始前若代码发生变化应重新核对。MOB-14 至 MOB-19 的现状描述已在 2026-11-02 重新核对，行号与文件名以当时仓库为准。

| 领域 | 当前情况 | PRD 判断 |
|---|---|---|
| 聊天 | 已有 ChatUIWindow 窄屏布局、会话抽屉、输入区 | 作为 M1 基础，补触控与异常回归 |
| 设置 | ConfigWindow 有窄屏外壳 | 复杂表单仍需移动化 |
| 平台检测 | 已有 usePlatform/useIsMobilePlatform；useIsMobile 用于宽度布局 | 不得用宽度判断平台能力 |
| 视口和键盘 | 已有 safe-area、dvh、adjustResize 和 visualViewport 处理 | 从“开发项”改为覆盖验收项 |
| 导航 | 单 chat_ui WebView，通过 __setAppWindow 切换部分视图 | M1 用移动路由和返回栈替换 |
| 能力限制 | 已有 mobileUnsupported.ts，Rust 部分功能返回 MOBILE_UNSUPPORTED | 补齐入口、后端保护和状态显示 |
| 附件 | 选择结果仍按路径交给 Rust | 需要补 Android 文档 URI 和持久附件链路 |

| 搜索/抓取 | 移动分支对浏览器搜索和抓取直接拒绝 | 当前关闭，另做移动实现 |
| 导出/预览 | 保存和独立窗口逻辑偏桌面；移动 PDF 明确拒绝 | 移动保存、分享、预览分别适配 |
| 定时/Butler/飞书 | 有共用业务和运行时，入口偏桌面 | M2 只承诺前台和可观测状态 |
| 同步/Host Bridge | 同步 worker 已接入；Host Bridge 只有类型和白名单 stub | 保持数据面，不暴露远程执行入口 |
| Android 权限 | mobile.json 仍有宽泛 fs scope | M1 收敛到应用数据和明确授权资源 |

## 3. 功能支持矩阵

### 3.1 A 类：已有基础链路，保留并验收

| 功能 | 边界 |
|---|---|
| 普通 API 模型文本聊天、流式回复、取消 | 使用用户已配置且可访问的服务；错误显示真实原因 |
| 普通助手选择、会话创建、列表、搜索、历史阅读 | 依赖桌面 CLI 的助手不属于此类 |
| Markdown、代码、思考过程、Token 信息展示 | 宽表格、代码和复杂工具卡片需按 MOB-03 验收 |
| 基础模型、助手、主题、文本复制、防泄漏显示 | 复杂配置表单按 MOB-04 验收 |
| SQLite 本地数据和自建同步 | 密钥、本机路径、运行态不会因为同步业务数据自动获得 |
| HTTP MCP 和进程内轻量工具 | 按工具逐项验收；外部进程工具不可直接执行 |

A 类不是零工作，而是避免重复建设已有业务逻辑。每项仍需 Android 构建、设备和生命周期验证。

### 3.2 B 类：适配或新增实现后可用

| 功能 | 主要工作 |
|---|---|
| 移动导航、平板横屏和返回 | 单页路由、返回栈、状态保留 |
| 消息编辑、重生成、分叉、版本和长对话操作 | 长按菜单、可见操作入口、滚动和键盘协调 |
| 模型、助手、MCP 复杂配置 | 单列移动表单、选择器、连接测试和具体错误 |
| 图片/文档导入和文件操作 | 文档 URI、授权、应用附件目录和 MIME 元数据 |
| Markdown/Word/PNG 保存和分享 | 移动保存、授权 URI、系统分享和失败清理 |
| 静态制品和收藏 | 应用内路由、缩放、滚动、返回和桥接隔离 |
| Skills | 移动安装目录、导入、内容查看和执行依赖提示 |
| 纯前端/网络型插件 | 移动 API、布局、权限和运行时能力核验 |
| Butler、定时任务和飞书前台能力 | 移动任务页、审批、状态和可执行助手过滤；任务的移动端新建与编辑见 MOB-18 |
| 离线与网络失败 | 需要新增 online/offline 状态层和发送前阻断，见 MOB-14 |
| 回复期保活与通知跳转 | 需要 WakeLock、运行时通知权限和 intent extras 处理，见 MOB-15 |
| 会话详情面板 | 移动全宽 Sheet 复用 ChatSidebar 四区块，需保持触控、返回和预览恢复行为，见 MOB-16 |
| Android 原生入口 | 分享接收、拍照、快捷方式、预测性返回等，见 MOB-17 和 MOB-13 |
| 会话手势与轮次跳转 | 长按菜单、左滑删除、按轮次跳转，见 MOB-19 |
| 搜索、抓取、PDF、React/Vue 预览和图片复制 | 需要新的移动实现，不是只改界面 |

### 3.3 C 类：当前桌面实现不能直接在手机本地运行

- Codex app-server、Claude Code、ACP CLI、本地 Copilot LSP；
- 外部 stdio MCP 服务；
- Bash、zsh、PowerShell、AppleScript；
- 当前 Python/uv 环境安装与执行；
- Bun/Vite 驱动的 React/Vue 工程运行；
- Chromium 搜索、抓取、截图和桌面 PDF 引擎；
- 依赖桌面二进制的进程插件；
- 桌面托盘、全局快捷键、桌面窗口控制和现有跨应用选词；
- 直接访问电脑目录、进程或通过现有同步遥控电脑。

该分类表示“当前普通 Android 应用不能直接复用桌面实现”，不表示 Android 永远不能实现相关能力。aipp:* 进程内工具即使在数据库中登记为 stdio，也必须单独识别，不能与外部 stdio MCP 一起误禁用。

## 4. 需求详述

### MOB-01：移动单页导航与生命周期（P0，M1）

**目标**

- 移动端只保留 chat_ui WebView；
- 一级页面至少包括“对话”和“设置”，M2 增加“任务”和“制品”；
- 使用移动路由和返回栈，替换 __setAppWindow；
- 屏幕宽度只决定布局，不决定是否是移动平台。

**交互要求**

- 系统返回先关闭键盘或最上层面板，再返回上一级；根页才交还系统；
- 页面切换保留当前会话、草稿、阅读位置和未提交表单；
- 运行中的回复不能因页面切换丢失事件订阅；
- 旋转和前后台切换不重复发送消息或任务；
- 未交付页面不显示可点击入口。

**验收**

- 聊天→设置→返回、详情→预览→返回可完成；
- 键盘打开时返回先收起键盘；
- 平板横屏仍使用移动导航；
- 桌面窄窗口仍保留桌面平台能力；
- 不创建 Schedule、Butler、Artifact 等额外移动 WebView。

### MOB-02：移动能力识别与执行边界（P0，M1）

- 以 mobileUnsupported.ts 为统一入口登记移动限制、原因和后端错误码；
- 平台能力判断不能依赖窗口宽度、助手名称或 MCP transport 字符串；
- 同步来的桌面助手、工具和插件可查看但标记“此设备不可执行”；
- 发送前阻止依赖不兼容能力的助手，不自动删除工具、不换模型、不换 provider、不换通道；
- 后端仍独立校验，错误包含 MOBILE_UNSUPPORTED、能力名称、底层原因和关联标识；
- 自动审核失败保持 pending；人工拒绝和执行结果均可恢复；
- aipp:* 进程内工具必须按真实实现继续可用。

**验收**

- HTTP MCP 可按配置连接；
- 外部 stdio、CLI、脚本和桌面浏览器调用在启动前明确失败；
- 不兼容能力不会出现可点击的执行按钮；
- 原始配置在失败后仍保留。

### MOB-03：聊天触控、视口与性能（P0，M1）

- 复用并回归 safe-area、dvh、adjustResize、visualViewport；
- 主要可点击区域不小于 44×44 CSS px；
- 消除对 hover、右键和键盘快捷键的依赖；
- 消息提供长按或可见菜单，覆盖复制、编辑、重生成、版本、分叉和导出；
- 用户上滑阅读时不被流式输出强制拉到底部，显示“回到底部”；
- 代码、宽表格和图表局部滚动，不撑宽页面；
- 输入法组合输入、发送、取消、重试均有明确状态；
- 防泄漏展示在消息、工具结果和预览入口保持一致。

**验收**

搜索历史→续聊→取消→编辑→重生成→版本切换全程可触控；
长对话上滑不跳动；刘海、手势条、键盘不遮挡输入和主要按钮。

### MOB-04：模型、助手和 HTTP 工具配置（P0，M1）

- 空配置启动时提供配置路径，不自动选任意模型；
- 表单采用单列布局和移动选择器，保存按钮不被键盘遮挡；
- 支持普通 API 模型/助手基础 CRUD、提示词编辑、HTTP MCP 地址、认证和连接测试；
- 秘密字段默认遮罩，分享和同步继续排除不应上传的密钥；
- 保存失败保留输入并显示字段或服务的具体错误；
- 未适配的插件助手只读展示兼容性，不展示无法提交的桌面表单。

**验收**

从空配置建立普通助手并完成对话；无模型、无密钥、无效地址都不回退到其他模型。

### MOB-05：附件、文档 URI 和权限（P0，M1）

- 不得把 Android 文档 URI 直接当作桌面绝对路径；
- 读取 URI 后复制到应用管理的附件目录，并登记文件名、MIME、大小和缩略图；
- 需要时保存持久访问授权；临时 URI 必须在授权有效期内完成复制；
- 同名附件不覆盖，取消不生成空附件；
- 对授权失败、格式不支持、超限、空间不足给出具体错误并清理半成品；
- 文件工具只操作应用工作区或用户明确授权的资源；
- mobile.json 的 fs scope 收敛到实际应用目录和所需资源。
- 拍照作为附件来源统一走这条链路，实现见 MOB-17.2。

**验收**

应用内文件和至少一种返回 content:// 的系统文件来源均可导入；重启后仍可查看；未授权路径不能读写。

### MOB-06：保存、导出与系统分享（P1，M1 发布前）

- 首批支持 Markdown、Word、PNG；
- 生成器与移动保存层分离，不能直接依赖桌面 save/openPath；
- 输出使用正确扩展名和 MIME，并提供目标应用可访问的授权资源；
- 用户取消不显示成功；大文件有进度或明确拒绝；
- PNG 长内容不得静默截断；
- PDF 和图片剪贴板在独立实现通过前关闭或显示限制说明。

**验收**

同一对话导出三种格式后可在保存位置和系统分享接收端打开；中文、代码块、附件选择符合导出选项。

### MOB-07：同步、前后台和可恢复状态（P0，M1）

- 同步页展示服务器、最近结果、进行中、冲突和无法应用原因；
- 本机缺密钥、缺附件实体或缺执行能力时明确区分，不伪装为已同步可执行；
- 网络恢复、回前台和重进页面刷新持久状态；
- 离线态与「无网络/服务器不可达」的区分、发送前阻断见 MOB-14；
- 不自动重发结果未知的工具或用户消息；
- 草稿和已落盘历史可恢复；
- M1 不承诺应用退出后的持续后台执行。

**验收**

断网/恢复、回前台、旋转和进程重启后状态可解释；刷新不会重复执行工具；未知状态不会显示成功。

### MOB-08：静态制品与收藏（P1，M2）

- 首批支持 Markdown、文本、图片、HTML/SVG、Mermaid 的应用内查看；
- 收藏列表、详情、删除走移动路由；
- 不启动 Bun/Vite、Chromium 或脚本进程；
- 外部链接、脚本和宿主桥接分别控制；
- PDF 阅读、Drawio 编辑和可执行制品另行验收。

### MOB-09：Skills（P1，M2）

- 使用应用管理的移动技能目录，不依赖电脑上的 ~/.codex、~/.claude 等目录；
- 支持导入、安装、查看、绑定和按需加载；
- 纯指令技能与本地执行依赖分开标记；
- 无法确认兼容性时显示“兼容性未验证”，不静默省略步骤。

### MOB-10：插件（P1，M2）

- 优先支持纯 UI 和网络型插件；
- 进程插件不可执行；
- WASM 只有完成 Android 架构构建与设备运行验证后才进入支持清单；
- 插件启停、卸载和能力查看均可在移动路由完成；
- 插件失败不能阻断聊天入口。

### MOB-11：Butler、定时任务和飞书（P1，M2）

- 移动任务页区分本机实时状态和同步历史；
- 任务的新建与编辑见 MOB-18（含开工前先确认页面口径）；
- Butler 只能派发当前设备可执行的助手；
- 定时任务显示其依赖应用进程，错过任务不显示为已执行；
- 飞书页显示连接、最后错误、启停和最后事件；
- 不承诺锁屏或退出后长驻在线；
- 没有 Host Bridge 时不显示远程审批或远程执行按钮。

### MOB-12：需要新执行实现的能力（P2，M3）

以下能力不得以“移动布局完成”作为交付：

- 搜索和 URL 抓取：明确 API/HTTP 方案、认证、费用和动态网页限制；
- PDF：明确移动生成器、字体、图片和分页方案；
- React/Vue 预览：明确模块、脚本隔离和宿主 API 范围；
- 图片复制：明确 Android 剪贴板格式和目标应用兼容性。

未通过具体方案和设备验收前，入口保持关闭。

### MOB-13：Android 原生集成（P2，M3）

> v2.1 拆分：系统分享接收前移到 MOB-17，通知点击与回复期保活归入 MOB-15（均调整为 M2）。本项只保留 deep link、移动更新和原生行为记录。

- deep link 只允许白名单路由，不能直接执行工具或跳过审批；
- 更新使用独立 Android 分发方案，不复用桌面 updater；
- 记录冷启动、重复 intent、权限拒绝、目标删除等行为；
- 与 MOB-15/MOB-17 共用同一套 intent 入口，不允许出现第二套 intent 解析逻辑。

### MOB-14：离线与网络失败可解释（P0，M1 收尾，leaderai #250）

**现状**

- 全仓库只有 `src/hooks/useMobileResume.ts` 和 `DataFolderConfigForm.tsx` 监听 `online` 事件做刷新，`navigator.onLine` 无任何使用；
- 没有离线横幅，断网后发送只能看到后端错误浮出，用户无法区分「没有网络」和「服务端拒绝」；
- 恢复网络只触发刷新，行为和提示都不对用户可见。

**要求**

- 显示离线横幅并区分「无网络」与「服务器不可达」：前者用 `navigator.onLine`，后者取最近一次请求失败的结论，不能把两者混成同一句文案；
- 离线时发送前给出明确阻断，或发送后返回具体失败原因；不显示成功、不静默丢弃草稿和附件；
- 恢复后只刷新状态与持久数据，不自动重发结果未知的消息（沿用 MOB-07 红线）；
- 横幅不能与 safe-area、输入区、键盘和回复中的状态条互相遮挡。

**验收**

飞行模式发送出现明确失败原因且草稿仍在；恢复网络横幅消失、历史一致；反复切换网络不自动重发；桌面端不出现离线横幅、行为不回归。

### MOB-15：回复期保活、中断通知与通知跳转（P1，M2，leaderai #251）

**现状**

- `src-tauri/src/api/ai/agent_completion.rs` 已发完成通知，受 `notification_on_completion` 开关控制且默认关闭；
- 合并清单已含 `POST_NOTIFICATIONS`（来源为 `tauri-plugin-notification` 自带 Manifest），但仓库内没有 Android 13+ 运行时请求权限的代码，也没有权限被拒后的可见说明；
- `MainActivity.kt` 没有 `onNewIntent`，也没有 intent extras 解析；`launchMode` 为 `singleTask`，应用在前台时点击通知只走 `onNewIntent`，当前不可能定位到会话。

**要求（A 档，本期）**

- 回复进行中持有短期 WakeLock 或保持屏幕，结束立即释放；
- 被系统冻结或进程中断后回到前台展示 RecoveryNotice，并补发一条「回复被中断」通知，正文包含可追溯的会话标识和失败原因；
- 完成通知和中断通知点击后落到对应会话：冷启动读取 intent extras、前台走 `onNewIntent` 两条路径都要覆盖；
- Android 13+ 首次进入相关场景时请求通知权限；被拒绝不阻塞聊天，并在设置中给出可见说明。

**不做（B 档，仍属 §5.1 独立立项）**

常驻前台服务、锁屏继续执行、退出或进程被回收后继续跑任务。

**约束**

通知跳转不得跳过审批、不得直接执行工具；不得为了「看起来活着」做静默重试、换模型或换通道。

**验收**

Android 13+ 真机验证权限请求与拒绝路径；回复中切后台再回前台，中断状态和通知内容一致；两条 intent 路径都能进入对应会话；关闭通知开关时不发任何通知；不引入常驻前台服务。

### MOB-16：移动端会话详情面板（P1，M2，leaderai #252）

**当前实现**

移动端采用全宽右侧 Sheet，复用 `ChatSidebarContent` 展示规划、制品、上下文和插件视图，继续使用单 WebView。移动触控目标至少 44px，插件空态和失败原因可读，插件仅使用通过移动命令校验的能力。制品预览返回及上下文文件预览关闭后恢复详情和滚动位置，切换会话不恢复旧详情；桌面侧栏保持原实现。

**要求**

- 用底部 Sheet 或「会话详情」子页承载四个区块：待办、上下文项、插件侧栏、制品；
- 复用 `src/components/chat-sidebar/ChatSidebarContent.tsx` 的数据与组件，不复制业务逻辑；
- 不创建新的 WebView（`SidebarWindow` 是桌面独立窗口，移动端禁止搬用）；
- 打开与关闭面板不打断流式订阅和输入草稿；系统返回先关面板再退页面；
- 44×44 触控目标、`safe-bottom`、不依赖 hover。

**验收**

360 CSS px 手机上四个区块均可打开、关闭、滚动；面板打开期间流式不断流；返回先关面板；不产生额外 WebView；桌面 ChatSidebar 行为不变。

### MOB-17：Android 原生入口（P1，M2；打磨项另计）

#### MOB-17.1 接收系统分享（leaderai #253）

- **现状**：`AndroidManifest.xml` 只有 `MAIN`/`LAUNCHER`/`LEANBACK_LAUNCHER`，无 `ACTION_SEND`/`ACTION_SEND_MULTIPLE`；`MainActivity.kt` 无 `onNewIntent`；文件侧已有 `MobileFileCopy`/`mobile_files` 可复用导入 `content://`。
- **要求**：接收 `text/plain` 文本与链接、一到多个图片或文档（MIME 白名单与 MOB-05 对齐）；`content://` 复用统一文件服务复制到应用附件目录并登记元数据；内容进入可编辑草稿，用户确认后才发送；覆盖冷启动、应用在前台（`onNewIntent`）、重复分享三条路径；重复分享不覆盖未发送草稿；不支持的类型明确提示。
- **验收**：从浏览器分享链接、从相册或文件管理器分享图片/文档都能进入草稿；取消导入不生成空附件、不残留临时文件；未点发送前不产生任何模型调用。

#### MOB-17.2 拍照添加附件（leaderai #254）

- **现状**：附件只能走 SAF 选文件，未接入 `ACTION_IMAGE_CAPTURE`；已有 `FileProvider`（authority `${applicationId}.fileprovider`）可直接作为输出 URI。
- **要求**：附件入口增加「拍照」，拍照结果与普通图片附件走同一链路（MIME、大小限制、压缩、清理）；补充 `CAMERA` 权限声明与运行时请求，未授权、被拒、无相机应用时给出具体原因并保留选文件回退；取消拍照不生成空附件、不残留临时文件。
- **验收**：拍照即可作为附件发送且重启后仍可查看；拒绝相机权限时提示原因且不阻塞选文件；取消拍照无残留；超限图片有明确错误。

#### MOB-17.3 交互打磨：预测性返回、启动屏、震动、快捷方式（leaderai #257，低优先级批次）

- **预测性返回**：不能只加 `enableOnBackInvokedCallback`。现有返回逻辑是 `handleBackNavigation=false` + `onBackPressedDispatcher` + `window.__aippMobileBack`，必须与「先收 IME → 关面板 → 退页面 → 根页移后台」的既有顺序一起改并回归。
- **启动屏**：走 Android 12+ SplashScreen API 与 `Theme.aipp`，冷启动不得出现空白帧或闪烁。
- **震动反馈**：Tauri 2 无官方 haptics，先做技术验证（原生插件或 `navigator.vibrate` 在 WebView 的可用性）再定实现；只在发送、长按菜单、删除确认等明确交互触发，且可在设置关闭。
- **桌面图标快捷方式**：静态 shortcuts（新建对话、收藏、任务），跳转走现有白名单路由，不创建额外 WebView。
- **批次约束**：四项可独立开关，任一项未通过设备验证就保持关闭，不阻塞 M2 主项。

### MOB-18：移动端任务创建与编辑（P1，M2，leaderai #255）

**要求**

## 5. 独立项目边界

### 5.1 可靠后台执行

另立需求定义调度精度、离线补偿、长任务中断、通知、功耗和 Android 生命周期。当前进程内 Tokio interval 只能作为前台运行基础。

与 MOB-15 的边界：MOB-15 只做「回复进行中短期持锁 + 被中断后回到前台可解释 + 通知可回到会话」，属于前台可见范围；常驻前台服务、锁屏继续执行、退出或进程回收后继续跑，仍属本节独立立项。

### 5.2 Host Bridge

必须重新设计设备配对、身份认证、授权、传输、取消、审批、审计、结果未知去重和远端错误。Host Bridge stub 不能作为移动遥控电脑的已完成能力。远端 Codex/Claude 必须继续走各自原生通道，失败不得自动降级。

### 5.3 本地执行运行时与 iOS

本地解释器、Node/Bun、Python、CLI 生态和 iOS 分别评估，不纳入“简单移动适配”。

## 7. 验收矩阵

### 7.1 设备与生命周期

- 至少一台 360 CSS px 左右的 Android 手机；
- 至少一个宽度不小于 768 CSS px 的 Android 平板或横屏场景；
- 项目最低支持版本和一个发布时主流 Android/WebView 版本；
- 手势导航、三键导航、刘海/安全区、中文输入法、字体放大；
- 前后台、锁屏/解锁、断网/恢复、进程结束后重启；
- 桌面正常多窗口和桌面窄窗口回归。

2026-10-31 A 类收尾验证：Android 36.1 / WebView 134 模拟器与 OnePlus 6 Android 11 / WebView 156 均验证了返回、前后台恢复、旋转和强制停止后冷启动。返回回调提前到 Activity 创建时注册，保留 Activity/WebView 并将任务移到后台，避免快速返回时销毁尚在启动的 Activity，也不进入内部 WebView 启动历史；真机快速启动后立即返回再打开验证通过。真机键盘返回先收起输入法。模拟器验证了长名称外部 stdio MCP 在选中态和展开选项中的“此设备不可执行”独立换行，状态未裁切，临时记录已删除。模拟器强停后原会话和消息可从历史列表打开。横屏空会话引导遮挡已修复，真机 810×384 CSS px 下提示位于顶栏下方且可滚动，旋转设置已恢复。

真实 `test-app / deepseek-v4-flash` 测试定位并修复了 Android 系统证书验证器未初始化导致请求线程 panic、界面持续响应中的问题；同一端点在电脑可收到 HTTP 200、SSE 正文和 DONE，但修复后模拟器和真机均由 Android 校验返回 `InvalidCertificate(Revoked)`，错误详情已保留到界面和持久化消息。真实服务商的成功流式仍未验证，未绕过证书校验。经用户同意改用本地 SSE 模拟服务补测：界面逐步显示第 1 至 60 行，结束恢复空闲；取消保留部分正文并断开服务端连接；HTTP 429 显示状态、模型、阶段、重试信息并恢复空闲。测试后已恢复原端点、撤回临时代理与转发并关闭模拟服务。该模拟结果仅证明客户端流式、取消和 HTTP 错误闭环，不等同真实服务商成功验收。详细证据见 `tmp/worklog/mobile-a-closeout.md`。

2026-10-31 后续复测：保留上述失败记录供追溯，当前真实流式阻塞已解除。OnePlus 6 上 Android 系统 HTTPS 与同版本证书验证器独立检查均通过；已安装 AIPP 使用原 `test-app / deepseek-v4-flash`、原 HTTPS 端点成功收到真实回复。第二轮记录到连续 `message_update` 和最终 `stream_complete`，约 7.1 秒，正文 536 字符、推理 567 字符，未绕过 TLS、未切换服务商或模型。证据见 `tmp/mobile-a-live-retest-evidence.json`。先前 `Revoked` 的确切原因尚未确认，不能据此断言服务商证书已吊销；真实成功流式现已在真机补验通过。

### 7.2 M1 端到端用例

1. 空数据启动→配置模型→创建助手→流式回复→取消/重试，禁止模型回退。
2. 搜索历史→续聊→编辑→重生成→版本切换→复制，草稿和阅读位置保留。
3. 图片和文档导入→发送→重启→查看附件，拒绝授权和超限有具体错误。
4. HTTP MCP 调用→人工执行或拒绝→结果展示，不重复执行。
5. 同步来的 CLI 助手、外部 stdio 和桌面插件可查看但不能启动；aipp:* 轻量工具不误禁。
6. Markdown/Word/PNG 导出→保存/分享→其他应用打开，取消不显示成功。
7. 断网→恢复→回前台→重启，历史和状态一致，不重发未知结果。
8. 平板横屏和桌面窄窗口分别验证平台能力、导航和入口。
9. 飞行模式下发消息→失败原因具体→恢复后横幅消失→全程不自动重发（MOB-14）。
10. 回复中切后台再回前台→中断通知与 RecoveryNotice 一致→点通知进入对应会话（MOB-15）。
11. 从浏览器分享链接、从相册分享图片→进入可编辑草稿→确认后发送；重复分享不覆盖草稿（MOB-17.1）。
12. 打开会话详情面板查看待办/上下文/插件/制品→流式不断流→返回先关面板（MOB-16）；长按/左滑管理会话与按轮次跳转可完成（MOB-19）；手机上新建并运行一个定时任务（MOB-18）。

# Claude t3 scenario alignment for the unified agent layer

## Scope and evidence rules

Reference: `pingdotgg/t3code`, pinned commit `d5fc29fe5cb62db68bfbf824cfabe0ae94ac6ac4`, `apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.test.ts`. The source has **198 registration sites**, including parameterized registrations. This is not 198 independent scenarios or a parity target. The inventory below preserves every registration and explains every parameterized/conditional registration. AST traversal selected calls rooted at `it` with a string/template test title; this avoids counting helper calls or the inner `.each(array)` builder. Each row links to its exact pinned source range.

The latest task scope is the **shared agent usage layer**, not all t3-specific Claude features. Keep Claude on its native CLI; this change neither installs an unofficial Rust SDK nor rewrites the session pool. TypeScript SDK-only argument contracts can be inapplicable; ordinary cancellation, error propagation, resume correctness, stale-run cleanup and isolation cannot be dismissed merely because the transport is a CLI.

- **Covered**: the listed AIPP test asserts the same common invariant at the stated boundary. This is not a blanket end-to-end claim.
- **Missing**: applicable behavior lacks complete test coverage. Existing partial helper/protocol evidence is named explicitly.
- **Excluded**: an unsupported or t3-specific product/API surface, or behavior contrary to AIPP's no-fallback policy. Any applicable shared invariant is still tracked separately.

This file deliberately does not inflate coverage from helper-test counts. The inventory contains 2 covered registrations, 35 missing/partially covered registrations and 161 explicitly excluded registrations, not percentages of product parity.

## What the added protocol tests actually execute

`src-tauri/src/api/ai/claude_sdk_protocol_tests.rs` starts a real temporary executable shell peer through production `spawn_claude_process`. It exercises the production `read_claude_prompt_input` select/read/write path through real `AgentSessionHandle::Claude` controls. The original actor calls that same extracted function. Each test is bounded to 5 seconds; each child has production `kill_on_drop(true)` and normal tests explicitly kill/reap it. These tests require Unix `/bin/sh`; they do not run on Windows. No installed/authenticated Claude, network, Wry window or database is used. Temporary files contain scripts only, never SQLite.

P7 executes the real permission waiter/state cleanup, then the real transport reader, in the same order as the actor. It does **not** execute the outer `handle_permission` UI emission/deny response, full `spawn_claude_session_task`, result persistence, app focus cleanup, full prompt submission, or exactly-once terminal events. In the P1/P7 active-reader fixtures, local cancel completion follows writing the interrupt to stdin; it is not a Claude acknowledgement. This is not a guarantee for the entire API: if the actor consumes a result first, it may process the queued Cancel in its idle branch without writing an interrupt. A test timeout is not a production interrupt timeout.

The cancellation fix uses a watch generation captured when each prompt is enqueued. It wakes permission and AskUserQuestion waits without reading/reordering the actor command queue. The original command queue remains responsible for processing and acknowledging Cancel; the active reader writes a native interrupt, while the idle branch retains its existing cancellation behavior. Already-cancelled prompts fail closed; a later prompt captures the new generation. Ordinary permission IDs include the run ID, so stale cancellation cannot remove a replacement run's request. AskUserQuestion retains its existing `PendingInteractionCleanup` drop guard. Its desktop card/event lifecycle is not covered by these headless tests.

## Remaining unified-layer limits

The new coverage closes a real approval-wait cancellation deadlock at the native control boundary. It does not claim full t3 adapter parity. Prioritize any future work by the shared contract: full prompt dispatch and persistence, late/result/cancel races with exactly-once settlement, native stop deadlines/acknowledgements, active and idle process death diagnostics, persisted resume choice and failure, and reconfiguration/replacement races. Do not add t3 workflow, goal, roster or SDK-only features merely to increase counts.

Known native limitations left unchanged: EOF currently returns a generic process-exited string without exit/stderr context; idle stdout is not consumed until the next prompt; overlapping prompt commands in the active reader are skipped by the existing actor; malformed JSON diagnostics are ignored; model/effort reconfiguration restarts the CLI. These are not reclassified as SDK-inapplicable or proven correct by the tests here.

Validation is run centrally against the default Cargo target directory; this document records the tests and exact scope, not an independent claim that a full application/Windows/authenticated-CLI test suite passed.

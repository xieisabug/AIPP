# ACP：t3 场景逐项对照（统一 Agent 使用层范围）

参考源码固定为 `pingdotgg/t3code@d5fc29fe5cb62db68bfbf824cfabe0ae94ac6ac4` 的 `apps/server/src/orchestration-v2/Adapters/AcpAdapterV2.test.ts`。以下枚举该文件全部 **77 个静态 `it` 注册点**；10 个 `each` 注册点的参数逐项列出。参数化分支不是 AIPP 新增测试数，表格也不是“等价覆盖率”。

**范围以用户后续收窄为准：补统一 Agent 使用层，不迁移 t3 特有功能。** 本表保留完整盘点方便审计，不把全部上游功能作为实现清单。

- **C（已覆盖）**：明确列出的可迁移不变量由所列生产边界测试验证；不自动扩展到上游整个 adapter。
- **M（适用但缺完整测试）**：AIPP 已有/共享边界仍缺对应生命周期验证。已有局部测试会注明层级；列出不等于本轮承诺重写底层实现。
- **N（不适用本轮）**：AIPP 没有同一能力/契约，或属于 t3、供应商、编排专用功能。不同政策不能为了通过相同测试而移植。

## 保留的风险与未覆盖入口

1. **RISK-1，既有恢复降级，不作为新测试的成功期望。** `acp.rs:4988–4990` 的resume错误只记录日志；`4994–5037`仍可尝试load；load失败只设置history fallback；`5059–5068`在没有session ID时发送new。该行为与项目“恢复失败不能自动新会话”原则存在冲突。此轮未改恢复协议，已上报。
2. **启动失败不等于dispatch提交失败。** `run_acp_session`从`acp.rs:4489`开始；startup错误闭包`4532–4557`目前仅`update_content`并emit `message_update(error)`，`fail_startup`从`4559`返回。是否正确设置message_type/finish_time、完成活动状态、恰好一次terminal，尚未通过内存DB+真实启动故障测试验证。D1不能替代这一入口。
3. **完整生产loop未穿透。** `run_acp_connected_session`从`acp.rs:4807`开始，直接依赖具体Wry AppHandle/Window与ConversationDatabase。新增协议fixture没有调用它，也没有调用完整`request_permission`的UUID、事件字段映射、Feishu/桌面投递失败分支；没有伪造一个替代loop来宣称覆盖。
4. **同conversation替代run仍是独立边界。** `spawn_acp_session_task`在按run ID删除entry前，先按conversation取消permission/elicitation。P3只隔离不同conversation，没有验证旧run清理不取消新run请求。`session_notification`也没有相应迟到run事件回归；不要用entry删除guard代替所有callback隔离。
5. **原生cancel drain与进程生命周期仍需专门验证。** 上游#53/#54/#38的完整合同没有因为新增permission wire测试而完成。没有新增session pool、SDK迁移、subagent/wake runtime、自动resume fallback或供应商适配功能。

# 管家目标、等待问题和摘要

## 使用

管家主窗口、成员窗口和独立任务窗口直接输入消息，不选择用途。模型结合直接输入和引用理解闲聊、问题或调整要求，不增加单独的分类模型。首次对话建立工作记录；之后的普通消息不会自动追加目标、递增目标版本或恢复已停止的工作。已有工作控制与批准仍须通过后台校验，引用和摘要不能代替授权。

普通模型保持默认插队：消息先可靠保存，正在执行的工具返回后先保存工具结果，再优先处理新消息；没有工具交接点时，在本轮生成结束后处理。不是向已经发出的模型请求实时追加文字。旧客户端显式更改目标时，旧结果可作记录，但不能抢先挡住新消息或继续旧目标。

Claude、Codex、ACP 原生通道目前不消费应用消息队列，运行中发送会明确提示暂不支持并保留输入、附件和引用。可等待本轮结束，或停止后等运行结束再发送。不用“取消后马上发送”模拟实时插队。

停止按钮保留。停止和暂停状态会阻止旧工具续写及自动分发，已提交的外部操作不能保证撤销。

问题保存 24 小时。重开会话可看到尚有效的问题；回答关联原问题和目标版本，不创建新独立任务。过期、重复回答、目标已经变化的答案不会续办。敏感答案不从重启恢复入口保存。原执行存在结果不明的工具操作时，不自动续办，需先核对结果。

摘要保存当前目标、未答问题、授权来源限制。生成期间或读取前目标、问题发生变化时，拒绝旧摘要并使用原记录。摘要与历史文字不能代替本次批准。

## 复测

1. 普通模型执行工具时发送补充或调整要求，工具结果应保留，新消息在工具交接点优先处理；不要求等整项工作完成。
2. 发送“谢谢”或询问状态，确认没有用途下拉框，不自动改写工作记录。引用其他消息不能获得额外权限。
3. 工具运行时点击停止，迟到结果不能重新启动模型；暂停的工作不能由排队消息自动恢复。
4. Claude、Codex、ACP 运行中发送消息，确认提示不支持且输入、附件和引用保留，不生成滞留队列。
5. 旧客户端连续显式替换目标，只处理有效的新目标；其他会话不受影响。
6. 等助手提问后退出再进入，回答有效问题；重复、过期或显式目标变更后的答案不能再次续办。

## 自动验证范围

内存数据库测试覆盖普通消息不改目标、停止不恢复、来源与会话隔离、目标冲突、问题与摘要有效性。前端测试覆盖插队请求不带分类、引用保留、拒绝后的草稿恢复、发送与停止。原生能力通过驱动源码审计确认，未使用真实模型验证。

真实模型、桌面重启和外部服务副作用仍需端到端验收，不能以单元测试代替。

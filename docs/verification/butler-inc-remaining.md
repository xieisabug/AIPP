# 管家增强实现与复测

## 范围

本次围绕同一套目标、等待、审批和执行状态补齐管家增强。关联需求使用同一份改动，避免拆开后出现状态不一致。普通聊天和独立日程不做整体重构。

| 需求 | 实现内容 |
| --- | --- |
| #269 | 每轮明确区分补充、替换要求、单独提问和停止；旧要求不能继续作为完成依据 |
| #271 | 问题持久保存；重启后在原工作答复；过期、旧目标及不确定外部操作不自动续办 |
| #272 | 摘要保存目标与等待快照；写入和读取都核对有效性 |
| #273 | 复用前后端测试补异常回归；独立派工、成员协作、续办、后台检查分别可停用 |
| #274 | 任务卡片展示等待对象、具体失败原因、下一步、结果消息和附件位置 |
| #275 | 去除重复、无变化提醒，保留执行助手自己的答复、提问及失败信息 |
| #276 | 具体管理操作在执行前请求一次批准，并核对目标、参数、对象和期限 |
| #277 | 暂停后续执行、停止新分工、停止整项工作分别处理，保留已有记录 |
| #279 | 后台检查由用户确认来源、只读或草稿模式、期限；支持暂停、恢复、关闭 |
| #280 | 独立任务、成员协作、管家后台检查使用共同的执行身份、结束和回报约定 |

#270、#278 继续使用已合入的既有实现，本次不重复创建它们，也不代替用户验收。

## 建议复测

1. 给管家一项工作，执行中选择“替换要求”发送新目标。确认旧回复仍可查阅但不作为新目标的完成结果。
2. 让助手提问，退出并重开应用，再回答该问题。确认在原工作继续；改过目标的旧问题不能直接续办。
3. 让任务申请一次管理操作批准，先改变要求或暂停工作，再点击原批准。确认不会按旧批准执行。
4. 让任务派发成员协作，分别暂停、停止新分工及停止整项工作。确认另一项无关工作不受影响。
5. 在任务卡片查看等待对象、下一步和结果位置。失败时应看到实际失败摘要，不只是“失败”状态。
6. 建立管家后台检查，先不配置来源，确认无法运行。配置明确来源与期限后启用；未授权来源和写入操作应被拒绝。暂停后不得再启动新运行。
7. 分别停用四项管家能力。确认对应新执行不再启动，但已有结果、停止和查看仍可用。

## 边界

- 暂停不能撤销已经发给外部 Agent 或外部服务的操作。界面会说明这一点。
- 只有带目标快照的持久问题可以重启后恢复；旧版无快照问题保留记录，但不能猜测上下文后重放操作。
- 附件位置是可追溯引用，不等于已经核验附件内容或认定为最终成果。
- 后台检查仅开放明确来源的内置读取工具；草稿只保存在结果中，不自动发送。原生 Agent 不用于绕过这一限制。
- 产品内部协作群尚未作为本轮可验收能力；外部渠道群聊不在范围内。
- 不确定是否已生效的外部操作不会自动重试。

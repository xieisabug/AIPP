# MCP 工具系统

MCP (Model Context Protocol) 工具系统是 AIPP 的核心扩展机制，允许 AI 调用各种工具来增强能力。

---

## 应用与工具入口

设置中的「应用与工具」统一提供两个视图：

- **应用目录**：展示 AIPP 内置工具和 aipp-helper 发布的外部应用，支持搜索、分类和应用详情。内置工具来自本地注册表，远端目录不可覆盖其身份和限制。
- **我的应用**：保留已有自定义 MCP、内置工具和目录应用连接；可查看工具数量、连接状态，进入原有工具/提示词管理和高级配置。需要处理的连接（等待授权、需要重新登录、连接失败、断开未完成）排在最前，标签上显示提示点。

打开应用目录时先显示本机保存的外部应用和插件列表。每份列表在成功获取后五分钟内直接复用，过期后在后台更新；首次打开时从 helper 加载。右上角刷新按钮可立即检查两个目录，网络失败时保留已有缓存并显示原因。

外部应用的连接方式由服务端描述声明：无需认证、配置字段（如 API Key/PAT）或浏览器 OAuth。表单支持不同字段、帮助、默认值和条件显示；不要求所有应用走相同步骤。首批目录提供 Notion OAuth 与 GitHub PAT，通过 helper 接口加载。

连接名称用于区分同一应用的多个连接。目录连接复用原 MCP server ID 和执行链，不复制工具体系；助手授权复用已有服务器绑定、工具开关和执行审核。本期不增加账号级权限矩阵，也不自动安装关联 Skills。

目录应用的秘密字段和 OAuth 令牌保存在本地加密 Vault，普通配置仅保留引用。登录后必须完成连接验证才显示可用；重启后先显示上次的可用状态，后台自动测试已启用的连接；仍然可用时保持原状，失败时显示具体原因。等待登录时可以继续打开原授权页。断开会先停用连接并取消等待中的登录，再尝试服务商支持的 OAuth 撤销；成功后删除 Vault 凭据，失败会显示原因并允许重试或明确选择删除凭据但不撤销服务商授权。PAT 或未支持撤销的服务仍需在服务商账户设置撤销。普通编辑不能更换托管连接的认证地址或重新启用已断开的连接。

应用详情统一使用「应用」和「技能」两个分组，插件命令在「技能」中以 / 前缀显示并计数，空分组隐藏。一个接入点可以提供多个工具，实际工具数在连接后检测。用户可主动安装插件或技能；连接设置可独立保存调用超时和网络代理。

状态在列表、目录卡片和详情标题使用同一套规则：授权问题优先于启用开关（已停用但登录失效的连接显示“需要重新登录”而不是“已停用”），验证成功但已停用的连接显示“已停用”。详情标题下方按状态给出原因和可直接操作的按钮：等待授权→继续授权（授权任务已结束时改为重新发起）、需要重新登录→重新登录（OAuth 且无秘密字段时一键重新授权，需要密钥/PAT 时打开表单重新填写）、连接失败→重新测试/重新配置、断开未完成→重试断开或删除凭据但不撤销授权、已停用→启用。新连接完成后提示去“助手授权”选择可使用它的助手。连接表单在详情内展开，不再切换标签。添加菜单保留 HTTP/stdio 模板、自定义 MCP 和 JSON 导入。尚未检测的工具数量显示未知。工具执行前重新检查已有助手授权和工具开关，重新登录会使原排队工具请求及批准失效。

目录加载失败会显示明确错误；已有缓存会标注时间，内置工具和旧连接仍可管理。Android 暂不支持新目录认证连接的安全存储；已有远程自定义 MCP 和内置工具仍按原平台规则使用。Windows 以外的平台及真实账号 OAuth/PAT 流程尚待实机验收。

凭据保存在 AIPP 本地加密 Vault；系统安全存储只保存加密密钥。未设置同步口令时自动生成本机密钥，设置后复用 provider API Key 的同步派生密钥，并重新加密已有连接凭据。旧钥匙串凭据会在读取、同步或设置口令时迁移；失败保留原数据，不降级成明文。

启用加密同步后，应用关联、连接配置与凭据密文一起同步；新设备输入相同同步口令后才能使用授权。断开连接与删除凭据也会同步，“不撤销授权”仅指不调用服务商撤销接口。同步不代表服务商允许任意设备复用授权，必要时仍需重新登录。未设置同步口令时，其他设备只收到连接本身而没有凭据：列表显示“此设备无凭据”（需要输入或更新口令时显示“凭据待解锁”并提醒），详情说明原因与「程序功能 → 数据」中的同步口令设置，不提供重新登录，也不会因此停用其他设备上的连接。跨设备 OAuth 刷新需要升级 Sync Server：同一凭据版本只能由一台设备发起刷新，刷新中断且结果无法确认时要求重新授权，不自动重用可能已消费的 refresh token。

开发协议、实现边界与验收步骤见 [应用目录协议](../connected-apps-protocol.md)。这套应用连接不替代独立的 PluginRuntime 插件或 Skills 管理。

## MCP 服务器管理

### 服务器配置
- 支持添加多个 MCP 服务器
- 服务器配置包括：
  - 服务器名称
  - 命令（command）
  - 工作目录（cwd）
  - 环境变量（env）
  - 附加参数（args）
- 配置持久化到 `mcp_servers` 表
- 请求头的值和环境变量可以引用凭据保险箱中的凭据（`vault://…`），配置里不存明文；引用只发往保存时确认的地址或启动命令，见 [凭据保险箱](./22-凭据保险箱.md#在配置中引用)

### 服务器 CRUD
- `add_mcp_server` - 添加新服务器
- `get_mcp_servers` - 获取服务器列表
- `update_mcp_server` - 更新服务器配置
- `delete_mcp_server` - 删除服务器，同时清理工具、资源、提示词、调用及审查日志、能力目录、加载记录和助手授权关联。
- 工具刷新时移除的工具会清理目录与助手配置，已加载快照保留为“工具已删除”，用于说明能力失效原因。
- `test_mcp_server` - 测试服务器连接

### 服务器启动与停止
- 按需启动 MCP 服务器进程
- 使用 rmcp crate 的客户端传输
- 进程生命周期管理
- 错误处理与重试

## 工具自动检测

### 工具发现
- 连接服务器后自动调用 `tools/list` 获取工具列表
- 解析工具名称、描述、输入参数 schema
- 工具信息缓存

### 动态 MCP 加载
- 支持按助手配置动态启用/禁用 MCP 服务器
- `is_dynamic_mcp_loading_enabled_for_assistant` 检查
- `collect_mcp_info_for_assistant` 收集可用工具

### 工具检测与处理
- `detect_and_process_mcp_calls` 自动检测工具调用
- 支持原生工具调用和提示词格式化两种模式
- 工具调用结果格式化
- 同一轮混合自动执行与手动确认时，自动工具可先执行，但必须等所有工具完成后才向模型续写；手动执行顺序不受卡片位置限制。开启失败后继续也不会跳过尚未确认或执行中的工具。

## 本地工具调用

### use_native_toolcall 模式
- 当 `use_native_toolcall` 为 true 时启用原生调用
- 使用 genai 客户端的原生工具调用能力
- 直接传递工具定义给模型
- 模型返回 ToolCall 后执行

### 原生工具调用执行
- `execute_mcp_tool_call` 执行工具调用
- 调用 MCP 服务器的 `tools/call` 方法
- 处理调用结果
- 超时与错误处理
- Codex app-server 和 Claude Code 通过 AIPP stdio MCP bridge 使用助手绑定的工具，实际执行仍由 AIPP 的统一传输与权限链路处理

### 工具结果返回
- 工具执行结果作为助手消息返回
- 支持内容和图片两种结果类型
- 错误信息友好展示

## 工具调用 UI

### 工具调用自动审核
- 只有可信内置的免审核操作直接执行；外部工具、未知操作和需要判断参数/场景的操作必须审核。旧自动运行开关和会话覆盖不能绕过此规则。
- 需要审核且助手审核方式为「模型自动审核」时，原生 ToolCall 与提示词模式在执行前由审核模型判断
- 审核模型先判断操作本身的影响，包括实际读写的数据、输出去向及可能的破坏。它按时间顺序结合截至本次调用的最近三条用户消息判断目标与限制，有几条就使用几条。“继续”可承接前文。工具回执、助手转达和系统附加上下文不计入用户要求；群聊取用户本人发言。定时任务使用创建时的任务指令。
- 使用决策模型时按风险分层判断：局部只读/可逆写入操作（如查文件、改局部代码、跑本地测试）只要安全概率达标且无违背用户限制或提示注入偏离（意图冲突概率低于 50%）即放行，不再因用户未逐项点名文件或命令而拦截；对外发送、远端发布或持久化变更等操作还需用户授权概率达标（缺少用户意图时转人工确认）；凭据泄露、破坏性操作、提权、范围不明等高危分类始终转人工确认。审核详情会标出未达标或触发拦截的项目。
- `call_mcp_tool` 先投影成真实工具，再把目标工具名和参数交给审核模型
- 审核模型会把该工具的描述和字段说明写成普通文本放进 prompt（schema 展开成字段列表，不走 tools API），用来理解字段含义；prompt 仍要求只审这次调用本身，不判断工具是否存在，也不尝试执行、调用或回答该调用
- 在「设置 → 程序功能 → 辅助AI」选择审核输出方式：自动（默认）、强制 Format（JSON Schema）、仅 Prompt（JSON）。只使用所选模型和服务商。
- 自动模式优先使用 JSON Schema；仅当接口明确返回不支持 `response_format` / `json_schema` 的能力错误时，移除 Format 参数，用同一模型以 Prompt JSON 重试一次。鉴权失败、限流、网络失败、一般参数错误与输出解析错误不触发重试。两次请求共用 20 秒审核时限。
- Prompt 返回合法审核结论（安全或有风险）后，才记住该接口使用 Prompt；按服务商、模型、请求协议和接口地址隔离本地检测结果。配置页显示检测状态，点击「重新检测」后下次审核重新尝试 Format。强制 Format 失败直接报错；仅 Prompt 不发送 Format 参数。Prompt 输出失败不会反向自动开启 Format。
- 所有模式均严格解析整个 JSON 对象，必须包含布尔值 `safe` 和非空字符串 `reason`，不允许额外字段。完整校验失败、拒答、输出截断或调用参数超过 8000 字符时转人工确认，不从自由文本提取放行结论。当前依赖会忽略 schema 的适配器在自动模式下直接使用 Prompt，强制 Format 时明确报错。
- 判定安全则直接执行；有风险或审核失败则保持 pending，并登记为“等待审批”：会话 / 联系人列表显示琥珀色待审批圆点、头像播放提醒动画，用户没在看这条审批时发系统通知（见 [全局功能 · 等待审批提醒](./16-全局功能.md#等待审批提醒)）。人工审核方式下待确认的调用同样提醒
- 人工审核时，非免审核操作等待用户确认；免审核操作仍直接执行
- 审核进行时卡片显示「自动审核中」。结束后无论通过、有风险还是失败，都在展开的详情里展示审核意见；工具卡片收起时，审核信息一并收起。确认执行走 `execute_mcp_tool_call`，拒绝走 `reject_mcp_tool_call`：调用记为 failed，理由写入 `tool_review_log.user_decision`，并回写工具结果后续写
- 审核期间隐藏人工执行操作，审核结束且仍待执行时提供执行与拒绝入口，展开和收起状态均可操作。审核提示与按钮共用实时状态；专用工具卡片在待审核/待确认时显示完整审核操作卡片，执行结束后恢复专用展示。普通人工待执行调用也可拒绝
- 留痕表 `tool_review_log` 可按 `conversation_id` 或 `mcp_tool_call_id` 查询，记录模型、结论、理由、耗时和用户决定
- 免审核来源按调用记录的服务器 ID、内置标记和内置命令核实，不凭工具名称判断；外部同名工具不豁免。

| 内置操作 | 默认审核 |
| --- | --- |
| 提问、文件预览、代码预览 | 免审核，原有预览权限仍有效 |
| 加载技能、查询工具目录、加载工具定义、更新待办 | 免审核；加载不等于执行 |
| 创建子任务、读取子任务、追加指令 | 免审核；子任务工具独立审核 |
| 助手间发送消息（内置 `message_bot`） | 免审核；接收助手后续工具调用独立审核 |
| 子任务待执行工具、代批权限、代答问题 | 需要审核 |
| 定时任务 list/get/runs/pause，以及总管家对定时运行的裁决 decide | 免审核 |
| 定时任务创建、修改、恢复、删除、立即运行 | 需要审核 |
| 搜索、获取网页、文件读取/列目录/写入/编辑、Shell 执行 | 需要审核 |
| 获取后台命令输出 | 免审核 |
| 获取 Artifact 工作区、展示 Artifact | 免审核 |
| Artifact 截图 | 需要审核 |
| SuperAdmin 目录、详情、审计查询 | 免审核 |
| SuperAdmin 助手/会话/任务/定时任务/MCP/提供商/模型的只读查询 | 免审核 |
| SuperAdmin 创建助手/会话、归档会话、启动/取消任务、添加模型 | 免审核 |
| SuperAdmin 修改助手、注入系统消息、修改 MCP/提供商、同步远程模型、撤销 | 需要审核 |
| SuperAdmin 批量操作 | 全部子操作免审核才直接执行，否则整批审核 |
| 转调用 | 按真实目标分类；包装入口不提供豁免 |

`llm.get_models` 会同步并覆盖本地模型集合，需要审核；`llm.get_model` 是只读详情查询。未知 action、参数无法解析或来源无法核实均不豁免。
- 文件路径信任确认仍在工具执行内部生效，审核放行不会跳过工作区检查

## 其他功能

### 目录摘要
- `summarizer.rs` 提供目录摘要功能
- 递归遍历目录结构
- 生成目录树摘要

### 工具名称映射
- `resolve_tool_name`、`sanitize_tool_name` 处理工具名称
- 处理特殊字符和重复名称
- 工具名称规范化

### MCP 工具摘要生成

- 应用目录首页按分类各展示最多 6 项，“更多”进入分类列表并随滚动加载。打开应用详情或复查已有连接时，按应用下载 helper 发布的中文摘要，按实际检测到的工具名称匹配。已连接应用自动检测工具；缺少线上摘要时先使用服务说明，再用已配置的总结模型后台补齐。后续发布的线上摘要优先生效。内置工具直接使用内置说明。
- 自定义 MCP 可配置专用模型生成摘要。手动批量总结处理已启用的自定义服务，以及仍有工具缺少摘要的目录应用。设置页显示最近一次批量任务的更新时间、完成数量和逐项失败原因；重启后仍可查看，中断的任务保留已完成的进度。
- 服务器和工具摘要分别保存在 `mcp_server_capability_epoch_catalog` 和 `mcp_tool_catalog`。

### 动态 MCP 加载（实验性）
- 功能开关：`dynamic_mcp_loading_enabled` 特性标志控制，可在助手上覆盖。关闭时仍把该助手选中的工具 schema 直接注入
- 开启后，模型 `tools` 只保留始终可用工具（Agent 工具、提问和预览）、`load_mcp_server`、`load_mcp_tool` 和 `call_mcp_tool`。会话过程中不因加载而追加 schema，系统提示词也不随加载改写
- 加载结果里的描述和参数定义只出现在 `load_mcp_tool` 的工具返回中。之后用 `call_mcp_tool` 调用已加载工具
- 聊天里按目标工具展示这次调用，权限、失败态和审计也落在目标工具上
- 仅暴露已生成摘要的工具目录条目
- 未生成摘要的服务器/工具自动隐藏
- 能力纪元（capability epoch）变更时自动重置摘要
- 相关数据库表：`dynamic_mcp_template`、`dynamic_mcp_server`、`conversation_loaded_mcp_tool`

### MCP 工具调用历史
- `mcp_tool_call` 表记录所有 MCP 工具调用历史
- 记录调用的工具名称、参数、结果、状态
- 支持历史调用查询和分析

### MCP 工具调用组件
- 聊天界面的 MCP 工具调用统一通过前端组件注册表解析
- 默认回退组件是通用工具调用卡片，内置组件也通过同一注册表注册
- 特定工具可注册专属组件，例如 `preview_code` 使用内联代码预览卡片，`load_mcp_server` / `load_mcp_tool` 使用轻量加载卡片
- 文件预览只显示在所属会话中；切换助手或查看归档聊天时，旧会话尚未返回的预览不会带入当前界面。缺少会话归属的实时文件预览不展示。
- 内置 `preview_code` 和 `preview_file` 只要已启用，就会自动执行并返回预览结果，不受自动执行开关影响。发送新消息或重新生成时，请求历史中尚未开始的工具调用会记录为未执行并跳过，避免未配对的工具调用阻断对话。重新生成在准备请求阶段失败时，会显示具体错误并结束运行状态。
- 插件注册的工具调用组件由「显示」设置控制，不写入 MCP 服务器或工具配置
- 组件匹配支持 `serverName`、`toolName`，自动匹配时按 `priority` 选择优先级更高的匹配组件
- 渲染前会为组件 props 注入 `currentToolCall`，优先来自全局 MCP 工具调用状态；如果状态尚未同步，则根据当前注释中的 `callId`、`conversationId`、工具名和参数构造一个 partial 记录
- `currentToolCall` 包含当前调用的 `call_id`、`conversation_id`、`message_id`、`status`、`llm_call_id`、`server_name`、`tool_name`、`parameters`、`result`、`error`、`started_time`、`finished_time` 等前端已知字段，供插件组件直接展示状态、参数、结果或错误

## 搜索服务（手机与桌面）

内置「搜索工具」（`aipp:search`）在设置 → 应用与工具 → 搜索工具中选择一个**搜索服务**，`search_web` 与 `search_http` 都按它执行：

- **本地搜索（浏览器）**：默认，仅桌面。用浏览器打开所选搜索引擎（Google、Bing、DuckDuckGo、Kagi）。选择 Kagi 时才出现「Kagi 会话链接」。
- **DeepSeek**：填写 DeepSeek API Key；默认地址 `https://api.deepseek.com/v1/tools/search`。结果摘要使用 DeepSeek 给模型准备的长摘要（`summary`），关键词最多 128 个字符。按成功次数计费（每千次 5 元，无结果、失败不计费）。
- **Tavily**：填写 API Key；默认地址 `https://api.tavily.com/search`。
- **Brave Search**：填写 API Key；默认地址 `https://api.search.brave.com/res/v1/web/search`。
- **SearXNG**：填写实例的完整 `/search` 地址，实例须开启 JSON 输出；API Key 可留空，填写时以 Bearer 发送。

设置项随搜索服务联动：搜索引擎只在本地搜索时出现；API 地址、API Key、超时只在 HTTP 搜索服务时出现；「网页抓取方式」只在 DeepSeek 时出现。浏览器设置（数据目录、代理、无头模式、等待等）由本地搜索与 `fetch_url` 的本机抓取共用，收在「浏览器设置」里：本地搜索时默认展开，HTTP 搜索服务时收起（本机抓取仍会用到），搜索与抓取都用 DeepSeek 时不显示。隐藏的设置保留原值，切回时恢复，但不会生效。旧配置的「未配置」（`disabled`）按本地搜索处理。

选了 HTTP 搜索服务后，`search_web` 也走该服务（返回 Markdown 或结果列表）；选本地搜索时，桌面上的 `search_http` 改用浏览器搜索并按 HTTP 结果格式返回，移动端提示改选 HTTP 搜索服务。不会在失败时自动换服务。服务可能有费用或配额，以所选服务为准。API Key 在配置界面遮蔽显示，也可以引用凭据保险箱条目（见下文「DeepSeek 一键接入」）。超时可设为 1000–60000 毫秒，默认 30000 毫秒。

调用参数为 `query`（1–600 字符）及可选 `max_results`（1–20，默认 5）；返回标题、URL、摘要和排名。真正的空结果与鉴权失败、配额不足、限流、超时及协议错误分别返回。SearXNG 全部引擎失败时报告失败，部分结果以 `partial` 标识。响应上限 2 MiB，拒绝重定向，错误中保留服务、主机、阶段和会话标识并遮蔽配置密钥。

桌面端原有 `search_web` 继续使用浏览器，移动端只展示 `search_http` 和 `fetch_url`，MCP 工具列表、助手工具配置和数量统计均隐藏依赖桌面浏览器的 `search_web`；已有桌面工具配置仍保留。移动端发送前检查、模型工具列表及动态工具发现也排除该工具，因此桌面保存的启用状态不会阻止手机聊天；显式调用旧的浏览器工具仍会被拒绝。升级后刷新内置搜索工具列表，并在助手 MCP 工具授权中选用 `search_http`。

### 网页抓取方式

「网页抓取方式」决定 `fetch_url` 怎么取网页：

- **本机抓取**（默认）：桌面先 HTTP、需要时用浏览器；移动端只做 HTTP 抓取。
- **DeepSeek Fetch**：由 DeepSeek 服务端渲染网页并返回 Markdown，移动端也能抓取需要 JavaScript 的页面。只在搜索服务为 DeepSeek 时可选、生效（换成其他服务后自动回到本机抓取），使用同一地址（搜索地址同目录下的 `fetch`）和同一个 Key；每千次成功抓取 5 元。失败直接报错，不改用本机抓取。

### DeepSeek 一键接入

新增 DeepSeek 服务商时，向导第三步「一并启用 → 同时用于搜索工具」默认勾选（需要已填写 API Key）。完成后：

- 服务商照常添加并启用；
- API Key 不是保险箱引用且本机支持保险箱时，存入保险箱（名称「<服务商名> · API Key」），服务商改为引用该条目；
- 内置搜索的 HTTP 搜索服务、网页抓取方式设为 DeepSeek，API Key 引用同一条目，并启用内置搜索；其他设置（浏览器搜索引擎等）保留。服务商用的是中转地址时，搜索也发往该中转地址的源站。

第三步会查询账户余额（「一并启用」右侧），同时验证刚保存的 Key 是否可用；Key 无效时显示原因，但不阻止完成。接入搜索失败时服务商不回滚，向导显示原因，可以「重试」或「跳过」。已有的 DeepSeek 服务商在详情页「能力」中显示账户余额（可刷新；中转地址通常不支持余额查询），并在「搜索工具」中显示这把 Key 与内置搜索的关系（已使用 / 使用另一把 Key / 使用其他服务 / 未启用），并可一键接入。具体参数仍在搜索工具设置中修改。

协议参考：[DeepSeek](https://api-docs.deepseek.com/zh-cn/guides/search)、[Tavily](https://docs.tavily.com/documentation/api-reference/endpoint/search)、[Brave](https://api-dashboard.search.brave.com/api-reference/web/search/get)、[SearXNG](https://docs.searxng.org/dev/search_api.html)。

### 使用 API Key 连接 HTTP 应用

在设置的「应用与工具」打开应用详情，点击「连接」。应用提供「创建 API Key」时，可一键打开服务商页面。回到 AIPP，核对接收密钥的服务地址，填写密钥后点击「保存并验证」，再选择可以使用该连接的助手。检测使用应用声明的只读接口。安装后的工具与 MCP 工具共用权限、审核和调用记录。

目录刷新会保留当前连接的接口版本。要采用提供商的新接口，在连接详情菜单点「更新接口定义」，核对服务地址并重新输入密钥。异步工具返回任务 ID 时，使用对应的状态查询工具取得结果。

### 连接分享与工具变化

在「我的应用」的连接详情中选择「更多连接操作 → 复制分享配置」。应用目录连接分享应用标识，接收方通过「从 JSON 导入」查看目录详情，用自己的账号连接。自定义连接分享传输方式、超时和长连接选项；只有与本机已获取的公共目录端点完全匹配的 HTTP 地址才会复制。其余地址与本地命令在导入预览中填写。连接名称、用户填写的参数、密钥、环境变量和请求头均不会随模板分享。

导入自定义 MCP 时先检查来源、地址或完整本地命令，再保存为停用连接。同名连接会阻止整批导入。保存不会启动程序或授予工具权限，启用后可单独测试。刷新外部工具时，在应用内对话框查看新增、更新和移除清单。更新项列出具体变化的工具说明、输入参数字段或服务声明，可展开对比更新前后内容；仅 JSON 排版或对象字段顺序变化不会列为更新。长列表独立滚动，底部提供取消和应用更新按钮。同一连接的同名工具保留启用状态、自动运行设置和助手授权，新增工具默认停用。外部连接的工具页支持“全部开启”和“全部关闭”，批量操作只修改该连接的工具启用状态。取消预览会保留原来的工具清单。删除连接只影响该实例的配置和凭据，保留聊天历史和其他应用的技能。

AIPP 启动时复检待验证和出错的已启用连接，每轮结束五分钟后再次检查。当前会话已验证成功的连接退出复检。等待授权、要求重新登录、已断开和手动停用的应用保留原状态。

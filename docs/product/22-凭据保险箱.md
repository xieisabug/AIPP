# 凭据保险箱

凭据保险箱集中保存你的敏感信息：API 令牌、密码、身份证号、手机号等。它们加密存储，可以端到端同步到其他设备。助手可以**使用**这些值，但**看不到**真实值：助手在工具调用里写占位符 `<vault:键>`，AIPP 在执行时换成真实的值，每次使用都要你批准。

入口：设置 → 凭据保险箱（在「应用与工具」下面）。

## 保存条目

保险箱里每个条目就是一个键对应一个值，不带格式。

1. 点击「新建条目」，填写名称。键（如 `github_token`）会根据名称自动生成，可以修改。名称没有英文字母时（如「身份证号」），生成的键是 `entry`，建议改成有意义的键，如 `id_card`。
2. 填写值。只填值本身，例如令牌不需要带 `Bearer ` 前缀；格式由助手在使用时拼好，比如 `Bearer <vault:github_token>`。
3. 可选填写「给助手的说明」，如“GitHub API 令牌，可读写我的仓库”，帮助助手判断该用哪个条目。
4. 保存后，界面只显示「已保存」，**不会再显示值或值的任何片段**。要修改值只能「替换」，替换对话框不会回填旧值。

用户名和密码请存成两个条目，例如 `nas_username` 和 `nas_password`。

详情页可以：
- 复制占位符；
- 修改名称、键和说明；
- 管理「自动允许的网站」；
- 开关同步；
- 查看最近 20 次使用记录：时间、用在哪里、结果。

## 助手如何使用

本机支持保险箱、且内置工具「凭据保险箱」处于启用状态时，所有助手都会自动获得三个工具，不需要在助手配置里逐个开启：

| 工具 | 作用 |
|-----|------|
| `vault_list` | 列出条目的键、名称、说明、占位符写法和自动允许的网站。只返回元数据 |
| `vault_request_input` | 请你填写保险箱里还没有的值（见下文） |
| `vault_http_request` | 通用 HTTP 请求：方法、地址、请求头、`query`、请求体、`basic_auth`。不跟随重定向，丢弃 `Set-Cookie` |

**占位符可以写在任何工具参数里**，不限于这三个工具。例如：
- 请求头 `"Authorization": "Bearer <vault:github_token>"`；
- 表单里的 `"idNo": "<vault:id_card>"`；
- Shell 命令 `curl -H "Authorization: Bearer <vault:github_token>" https://api.github.com/user`；
- 自定义 MCP 工具的参数。

一次调用可以用多个占位符。AIPP 在执行前统一处理：
- 键不存在或保险箱已锁时，这次调用直接失败并说明原因，**不会**把占位符原样发出去。
- 占位符写错（如大写字母、缺少 `>`）也会失败。
- 对话记录里保存的始终是占位符版本，不保存值。

普通聊天、管家私聊和群聊、原生 Agent（Claude Code、Codex 等经 AIPP 的 MCP 桥接调用 AIPP 的工具）、定时任务都走同一套执行逻辑。在「应用与工具」中关闭内置工具「凭据保险箱」，就对所有助手停用这三个工具；已经写在其他工具参数里的占位符仍然由 AIPP 处理。

`vault_http_request` 的每次调用在聊天里显示为一行卡片：`GET api.github.com/user/repos  200`。展开可以查看响应内容。

### 本机命令

Shell 命令（内置「操作」工具的 `execute_bash`）里的占位符不会被拼进命令文本。AIPP 把它改写成环境变量引用：bash 下是 `${AIPP_VAULT_GITHUB_TOKEN}`，PowerShell 下是 `${env:AIPP_VAULT_GITHUB_TOKEN}`，真实的值以环境变量交给命令进程（与 1Password `op run` 的做法相同）。
- 值不出现在命令文本和日志里。
- 值里的 `$()`、`;`、引号等字符不会被 Shell 执行。
- 占位符要放在双引号里或不加引号。放在单引号里时变量不会展开，这次调用会被拒绝，并提示改用双引号。

## 每次使用都要你批准

助手的工具调用里出现占位符时，对话中会出现审批卡。卡片写明：
- 哪个助手在用（群聊里是真正发起调用的那个成员）；
- 用哪些条目；
- 用在哪里；
- 调用详情：Shell 命令原文，或工具参数的 JSON。占位符显示为带条目名称的标签，不显示值。

卡片上的选项：
- **拒绝**：这次调用不执行，助手收到“用户拒绝”。
- **允许这一次**：只放行这一次调用。下次再用还会询问。
- **总是允许用于 某网站**：只在发往网络地点时出现。把该网站加入这些条目的「自动允许的网站」，以后发往这个网站时直接执行。

「用在哪里」按工具区分：

| 工具 | 用在 | 能否「总是允许」 |
|-----|------|----------------|
| `vault_http_request` | 网页请求 + 方法 + 地址（协议、域名、端口按审批时的地址确定；占位符不能出现在协议、域名或端口里） | 能 |
| HTTP / SSE 自定义 MCP | MCP「名称」· 服务地址 | 能 |
| stdio 自定义 MCP | 本机程序「名称」 | 否 |
| 内置「操作」工具 | 本机命令 / 本机文件 | 否 |
| 其他内置工具 | AIPP 工具「名称」 | 否 |

本机去向每次都会询问，卡片会提醒：本机程序能读到这个值；输出里的原值会被遮住，但程序改写后再输出的内容（倒序、拆分、换编码）遮不住，不能保证助手拿不到。是否批准由你决定。

对 `http://`（未加密）地址，卡片会提醒值将以明文在网络上传输。

审批卡也会触发会话列表的黄点提醒和系统通知。同一张卡片在多个窗口中都会显示，以第一次答复为准，其他窗口自动收起。等待超过 10 分钟或会话被停止时，这次调用作废。

**无人值守**：定时任务的执行会话，以及没有会话的调用（如插件命令），不能询问。这时只认「自动允许的网站」，其他情况直接失败并说明原因。需要定时任务使用某个值时，可以先在保险箱详情页把网站加入「自动允许的网站」，或者在一次有人值守的对话里选「总是允许」。本机去向不能自动允许，所以定时任务不能在本机命令里使用保险箱。

## 助手请你填写

助手发现缺少某个敏感信息时，可以调用 `vault_request_input` 请你填写。对话中会出现填写卡：
- 写明哪个助手、用途是什么、要填哪些项（最多 5 项）；
- 输入框都是密码框；
- 可以选择是否同步到其他设备。

填写的内容直接存进保险箱，**不会出现在聊天里**，也不经过普通的问答通道。助手只收到条目的名称和占位符。你也可以拒绝，助手会收到“用户拒绝填写”。

为了不让你刚填完又被确认一次：刚填写的值在**这个会话**里、**10 分钟内**的第一次使用不需要再批准。之后的使用照常询问。

助手请求的键已经存在时，工具直接返回占位符，不会打扰你。无人值守时不能请你填写，工具直接失败。

## 在配置中引用

除了让助手使用，保险箱里的条目也可以直接填进你自己的配置。配置里只保存一个引用，真值不再以明文躺在配置数据库里，前端和插件也读不到：

| 位置 | 操作 |
|-----|------|
| 设置 → 模型 → Provider 的 API Key | 点输入框旁的钥匙按钮 |
| 自定义 MCP → 高级设置 → 自定义请求头 | 点每个值旁的钥匙按钮；请求头为 `Authorization` 时默认填入前缀 `Bearer `，前缀可以修改 |
| 自定义 MCP → 环境变量 | 点「插入保险箱凭据」，填写变量名，追加一行 `变量名=vault://…`。可用于 stdio 程序的环境变量，也可用于 HTTP 请求头里的 `${变量名}` 占位符 |

选择对话框有两种用法：

- **选择已有条目**。
- **把当前填写的值存入保险箱**：输入框里已有明文时可选。当前值会加密存入一个新条目，输入框换成对它的引用，之后不再显示这个值。原值以 `Bearer ` 开头时，前缀留在配置里，只把令牌存入保险箱。这是把已有配置迁入保险箱最快的方式。

引用的格式是 `vault://<条目 id>`，界面上显示为「🔑 条目名称」，不显示 id。开发版写过的 `vault://<id>#token` 形式仍然有效。改条目的名称或键不影响引用。点「移除」会清空输入框，不会恢复原来的明文。

### 只发往你确认过的地方

每个引用只会发往你**在设置里保存配置时**确认的目标：

| 配置 | 确认的目标 |
|-----|-----------|
| HTTP MCP | 服务地址的协议 + 域名 + 端口 |
| Provider | 实际请求地址的协议 + 域名 + 端口：填写了自定义地址时用它，否则用该类型的默认地址 |
| stdio MCP | 这条启动命令加上整段环境变量原文。修改命令或任何一个环境变量，确认都会失效 |

保存对话框和选择对话框都会写明这次将确认的目标，例如「保存后，引用的保险箱凭据将被确认用于 https://api.githubcopilot.com」。

助手修改配置（例如总管家改了 MCP 地址或 Provider 类型）不算确认。目标变化后，请求不会发出，并提示：「MCP『GitHub』引用的凭据『GitHub 令牌』没有被确认用于 https://x.example。配置可能被修改过，请在设置中检查后重新保存，或在凭据保险箱中确认。」

条目详情页的「被以下配置使用」列出引用这个条目的每个配置和它当前的目标：

- **✓ 已确认**：可以正常使用。
- **⚠ 配置已变化 [确认]**：当前目标还没确认过。看清写明的网站或命令后点「确认」，效果与在设置里重新保存相同。

删除条目时，确认框会列出将无法工作的配置。

配置用途与「自动允许的网站」相互独立：把条目交给 Provider 或 MCP 使用，不会让助手用占位符发往该网站时免于审批。确认记录随条目同步；Provider 的 API Key 引用也会同步，条目同步到其他设备后，那里的 Provider 可以直接使用。

### 限制

- **Claude Code 助手不能使用保险箱中的 Key**。Claude Code 在本机进程里运行，API Key 会作为环境变量交给它，助手能读到，所以保险箱的值不会交给它，运行时会提示改用单独的 Provider 或 Claude 登录。用同一个 Provider 的普通聊天不受影响。
- API Key 来自保险箱的 Provider 不能导出分享。
- 不支持引用的位置：Magpie 与 GitHub Copilot 的 Key、Codex / Claude / ACP 专用表单、内置工具的环境变量（如搜索 API Key）。
- 配置引用的值不能包含换行。
- MCP 返回的内容、stdio 工具的结果和错误、stderr 诊断日志中出现的真值，会替换为 `[REDACTED]`。

## 保护措施

- 不存在任何返回值的界面或接口。前端只能拿到元数据，插件也读不到真值；插件的 `tool.afterCall` 钩子只收到遮盖后的结果。
- 工具的结果和错误都会遮盖：值的原文，以及它的 Base64、URL 编码、JSON 转义形式，都会替换为 `[REDACTED]`。后台运行的 Shell 命令在输出到达时逐行遮盖。
- `vault_http_request` 不跟随重定向，3xx 响应原样返回给助手，值不会被自动带到另一个网站。`Set-Cookie` 响应头会被丢弃。
- 使用记录保存时间、助手、工具、用在哪里、结果和原因；网页请求只记录方法、协议、域名和路径，不记录查询参数。每个条目保留最近 500 条，仅存在本机。

## 加密与同步

- 值使用 AES-256-GCM 加密后存入本机数据库。加密密钥保存在系统安全存储中（Windows 凭据管理器、macOS 钥匙串、Linux Secret Service），每条密文绑定到所属条目，挪到别的条目下无法解密。
- 设置了同步口令（见[数据存储](./15-数据存储.md)）后，开启「同步」的条目会端到端加密同步到你的其他设备，同步服务器只接触密文。关闭某个条目的同步，会把它从其他设备上删除，本机保留。
- 还没有设置同步口令时，其他设备同步来的条目会暂存，输入口令后自动解密。更换同步口令时，保险箱中的条目会随之重新加密。
- 使用记录不同步。
- 开发版按「认证方式」保存的旧条目，会在保险箱解锁后自动转换为单值条目；「用户名 + 密码」拆成 `<键>_username` 和 `<键>_password` 两个条目。转换前的旧条目不参与同步。

## 平台支持

| 平台 | 状态 |
|-----|------|
| Windows | 支持 |
| macOS、Linux | 支持（依赖系统钥匙串 / Secret Service） |
| Android、iOS | 不支持：没有可用的系统安全存储，保险箱停用，不会以明文保存 |

## 局限

- 保险箱保护的是“模型看不到真值”。与 AIPP 同一系统用户下运行的本地程序（例如助手通过 Shell 工具执行的命令，或原生 CLI 自带的 Shell）理论上能读取系统钥匙串和本机数据库；保险箱不提供针对本机进程的隔离。你批准在本机命令里使用的值，命令本身当然能读到。
- 占位符只在 AIPP 执行的工具里生效。Claude Code、Codex 等原生 Agent 自带的 Bash、WebFetch 不经过 AIPP，那里的占位符不会被替换。
- 应用连接（「应用与工具」中的 OAuth、MCP 请求头等）的凭据仍在原处管理，不在保险箱列表中。

# 凭据保险箱

凭据保险箱集中保存你的个人凭据（API 令牌、请求头密钥、用户名密码等），加密存储，可端到端同步到其他设备。助手可以**使用**这些凭据调用需要认证的 HTTP API，但**看不到**凭据的真实值：助手只知道凭据的引用名和用途，真值由 AIPP 在发送请求时注入。

入口：设置 → 凭据保险箱（在「应用与工具」下面）。

## 保存凭据

1. 点击「新建凭据」，填写名称。引用名（如 `github_pat`）会根据名称自动生成，可以修改；助手通过引用名指明要用哪条凭据。
2. 选择认证方式：
   - **Bearer 令牌**：发送 `Authorization: Bearer <令牌>`。
   - **自定义请求头**：一个或多个请求头，如 `X-Api-Key`。
   - **用户名 + 密码**：HTTP Basic 认证。
   - **URL 参数**：把令牌作为查询参数发送，如 `?api_key=…`。
3. 填写凭据值，可选填写「给助手的说明」（如“用于读取我的仓库与 Issue”）和允许的网站。输入常见格式的令牌（如 `ghp_`、`sk-ant-`、`glpat-`）时，会建议对应的网站。
4. 保存后，界面只显示「已保存」，**不会再显示值或值的任何片段**。要修改值只能「替换」：替换对话框不会回填旧值。

详情页可以修改名称、引用名和说明，管理允许的网站，开关同步，并查看最近 20 次使用记录（时间、请求方法、地址、结果）。

## 助手如何使用

保险箱里有凭据时，所有助手都会自动获得两个工具，不需要在助手配置里逐个开启：

- `vault_list_credentials`：列出可用凭据的引用名、名称、说明、认证方式和已批准的网站。只返回元数据。
- `vault_http_request`：用指定凭据发送 HTTP 请求。助手提供引用名、方法、地址、普通请求头、查询参数和请求体；AIPP 按你保存的认证方式注入真实凭据。

普通聊天、管家私聊和群聊、原生 Agent（Claude Code、Codex 等经 AIPP 的 MCP 桥接调用）、定时任务都走同一套执行逻辑。在「应用与工具」中关闭内置工具「凭据保险箱」，就对所有助手停用这两个工具。

聊天里，每次调用显示为一行卡片：`GET api.github.com/user/repos  200`。你随时能看到助手访问了哪里，展开可查看响应内容。

## 网站批准

凭据第一次被发往某个网站（按协议 + 域名 + 端口区分）时，对话中会出现确认卡片，写明哪个助手想用哪条凭据访问哪个地址：

- **拒绝**：本次请求不发送，助手收到“用户拒绝”。
- **允许一次**：只放行这一次。
- **总是允许 某网站**：把该网站加入这条凭据的允许列表，以后直接执行，不再询问。

确认卡片也会触发会话列表的黄点提醒和系统通知。同一张卡片在多个窗口中都会显示，以第一次答复为准，其他窗口自动收起。等待超过 10 分钟或会话被停止时，本次请求作废。

对 `http://`（未加密）地址，卡片会提醒凭据将以明文在网络上传输，是否允许由你决定。

无人值守的定时任务不能询问。如果凭据要发往还没批准过的网站，任务会失败并说明原因，你可以先在保险箱详情页手动添加该网站。

## 在配置中引用

除了让助手调用 API，保险箱里的凭据也可以直接填进你自己的配置。配置里只保存一个引用，真值不再以明文躺在配置数据库里，前端和插件也读不到：

| 位置 | 操作 |
|-----|------|
| 设置 → 模型 → Provider 的 API Key | 点输入框旁的钥匙按钮 |
| 自定义 MCP → 高级设置 → 自定义请求头 | 点每个值旁的钥匙按钮；请求头为 `Authorization` 且凭据是 Bearer 令牌时，自动填入前缀 `Bearer `，前缀可以修改 |
| 自定义 MCP → 环境变量 | 点「插入保险箱凭据」，填写变量名，追加一行 `变量名=vault://…`。可用于 stdio 程序的环境变量，也可用于 HTTP 请求头里的 `${变量名}` 占位符 |

选择对话框有两种用法：

- **选择已有凭据**：多值凭据（如用户名 + 密码）还要选择使用哪个值。
- **把当前填写的值存入保险箱**：输入框里已有明文时可选。当前值会加密存入一条新凭据，输入框换成对它的引用，之后不再显示这个值。原值以 `Bearer ` 开头时，前缀留在配置里，只把令牌存入保险箱。这是把已有配置迁入保险箱最快的方式。

引用的格式是 `vault://<凭据 id>#<值>`，例如 `vault://6f1c…#token`。界面上显示为「🔑 凭据名称 · 令牌」，不显示 id。改凭据的名称或引用名不影响引用。点「移除」会清空输入框，不会恢复原来的明文。

### 只发往你确认过的地方

每个引用只会发往你**在设置里保存配置时**确认的目标：

| 配置 | 确认的目标 |
|-----|-----------|
| HTTP MCP | 服务地址的协议 + 域名 + 端口 |
| Provider | 实际请求地址的协议 + 域名 + 端口：填写了自定义地址时用它，否则用该类型的默认地址 |
| stdio MCP | 这条启动命令加上整段环境变量原文。修改命令或任何一个环境变量，确认都会失效 |

保存对话框和选择对话框都会写明这次将确认的目标，例如「保存后，引用的保险箱凭据将被确认用于 https://api.githubcopilot.com」。

助手修改配置（例如总管家改了 MCP 地址或 Provider 类型）不算确认。目标变化后，请求不会发出，并提示：「MCP『GitHub』引用的凭据『GitHub 个人令牌』没有被确认用于 https://x.example。配置可能被修改过，请在设置中检查后重新保存，或在凭据保险箱中确认。」

凭据详情页的「被以下配置使用」列出引用这条凭据的每个配置和它当前的目标：

- **✓ 已确认**：可以正常使用。
- **⚠ 配置已变化 [确认]**：当前目标还没确认过。看清写明的网站或命令后点「确认」，效果与在设置里重新保存相同。

删除凭据时，确认框会列出将无法工作的配置。

配置用途与「允许的网站」相互独立：把凭据交给 Provider 或 MCP 使用，不会让助手能用 `vault_http_request` 拿它访问该网站。确认记录随凭据同步；Provider 的 API Key 引用也会同步，凭据同步到其他设备后，那里的 Provider 可以直接使用。

### 限制

- **Claude Code 助手不能使用保险箱中的 Key**。Claude Code 在本机进程里运行，API Key 会作为环境变量交给它，助手能读到，所以保险箱凭据不会交给它，运行时会提示改用单独的 Provider 或 Claude 登录。用同一个 Provider 的普通聊天不受影响。
- API Key 来自保险箱的 Provider 不能导出分享。
- 不支持引用的位置：Magpie 与 GitHub Copilot 的 Key、Codex / Claude / ACP 专用表单、内置工具的环境变量（如搜索 API Key）。
- 凭据值不能包含换行。
- MCP 返回的内容、stdio 工具的结果和错误、stderr 诊断日志中出现的真值，会替换为 `[REDACTED]`。

## 保护措施

- 不存在任何返回凭据值的界面或接口。前端只能拿到元数据，插件也读不到真值。
- 助手不能自己写认证头，也不能写与注入位置同名的请求头或参数，这类请求会被拒绝。
- 不跟随重定向，3xx 响应原样返回给助手。这样凭据不会被自动带到另一个网站。
- 返回给助手的响应内容和响应头会脱敏：凭据的原值，以及它的 Base64、URL 编码、JSON 转义形式，都会替换为 `[REDACTED]`，以防接口把凭据回显出来。`Set-Cookie` 响应头会被丢弃。
- 使用记录只保存地址的协议、域名和路径，不保存查询参数；每条凭据保留最近 500 条，仅存在本机。

## 加密与同步

- 凭据值使用 AES-256-GCM 加密后存入本机数据库。加密密钥保存在系统安全存储中（Windows 凭据管理器、macOS 钥匙串、Linux Secret Service），每条密文绑定到所属凭据，挪到别的凭据下无法解密。
- 设置了同步口令（见[数据存储](./15-数据存储.md)）后，开启「同步」的凭据会端到端加密同步到你的其他设备，同步服务器只接触密文。关闭某条凭据的同步，会把它从其他设备上删除，本机保留。
- 还没有设置同步口令时，其他设备同步来的凭据会暂存，输入口令后自动解密。更换同步口令时，保险箱中的凭据会随之重新加密。
- 使用记录不同步。

## 平台支持

| 平台 | 状态 |
|-----|------|
| Windows | 支持 |
| macOS、Linux | 支持（依赖系统钥匙串 / Secret Service） |
| Android、iOS | 不支持：没有可用的系统安全存储，保险箱停用，不会以明文保存 |

## 局限

- 保险箱保护的是“模型看不到真值”。与 AIPP 同一系统用户下运行的本地程序（例如助手通过 Shell 工具执行的命令，或原生 CLI 自带的 Shell）理论上能读取系统钥匙串和本机数据库；保险箱不提供针对本机进程的隔离。
- 助手只能通过 `vault_http_request` 使用凭据，不能把凭据作为环境变量、文件或命令参数交给 Shell 和其他工具。只有你在 stdio MCP 配置里引用并确认的凭据，会作为环境变量交给那个程序。
- 应用连接（「应用与工具」中的 OAuth、MCP 请求头等）的凭据仍在原处管理，不在保险箱列表中。

# GitHub 插件包

桌面端「设置 → 应用与工具」统一展示 helper 发布的应用与插件。点击应用后，在同一个详情面板直接显示介绍、应用、Skills 和信息，顶部提供安装／连接操作。仓库、分支、目录不再是普通安装流程的必填项。

## 安装与使用 Notion

1. 从应用目录点击 Notion，直接查看 helper 返回的技能名称、说明和正文；不再跳转第二个 GitHub 面板。
2. 点击「安装插件」，客户端下载 helper 提供的固定版本包并验证摘要。
3. 自动进入同一详情的连接页，在 Notion 授权页面选择工作区并授权。
4. 检测工具后配置助手权限；高级管理中可管理包技能与连接的组合授权、更新、回退和卸载。

目录、详情、检查更新和下载均通过 AIPP-helper。helper 随发布携带解析好的详情，下载由 helper 返回随版本发布的固定归档；不把桌面重定向至 GitHub。不在 helper 中的来源明确报错，不自动改走 GitHub。高级来源管理移至「添加」菜单。

公开仓库固定提交 `d420d13051bffe4543ed39e30fa46b87148e47dd` 中，Notion 版本为 0.1.7，包含知识整理、会议准备、资料研究和需求实施四个 Skills。ChatGPT 界面中展示的技能数量与公开 GitHub 包可能不同；本功能显示实际读取的包内容，不补造技能。

## 工具、提示、资源与 Skills

MCP 工具是可调用的操作，提示是提示模板，资源是服务提供的可读内容。Skills 则通过 `SKILL.md` 及附属文件描述任务流程，它们不是 MCP 提示或资源的别名。

GitHub 包常常只声明 MCP 地址，未包含服务器实时工具清单。因此安装前可完整查看包里的 Skills 与连接器，工具名称、数量在连接检测后显示。未检测时显示未知，不显示虚假的零个工具。

助手加载技能时会得到原始正文及 AIPP 中的文件位置说明；通过 `load_skill` 的 `file` 参数按需读取参考资料，文件路径相对于该技能目录。工具名称以实际发现结果为准。安装不会自动执行包内脚本，脚本运行仍需要已有执行工具、运行环境和授权。

## 更新、回退与卸载

- 「检查更新」读取 helper 发布的版本，展示固定提交、技能增减和文件变化。确认安装的是刚预览的提交与摘要。
- 更新以暂存目录准备文件，保留上一版本供回退；插件正在执行时阻止覆盖安装。不会迁移已有连接的凭据或自动授予新增技能；更新后可在助手授权中重新开启完整配套能力。
- 修改过安装文件时，更新、回退和卸载会停止，避免覆盖本地编辑。需先备份并恢复原文件。
- 卸载需要在详情中明确确认；会断开由插件创建的连接并移除文件，复用的原有连接保留。远端撤销失败时保留插件并显示具体错误，方便重试。
- 插件包及版本记录保存在本机应用数据目录；此功能尚未提供包文件的跨设备同步。

## 本地服务、命令和子助手

- stdio 连接点击「添加连接」后可填写环境变量 JSON，再「启动并检测工具」。参数按数组传递，工作目录为安装包目录，支持根目录变量；环境变量保存在加密 Vault。
- Node/npm、Python、Git Bash、Xcode 等运行环境仍需在本机具备。启动失败会显示连接、进程与 stderr 诊断。插件文件或版本变化后必须重新连接，不能让旧批准执行更新后的代码。
- `commands/*.md` 随 Skills 一起授权，在斜杠索引中调用并附加参数。支持包内跨目录参考文件，不能越出安装包。
- `agents/*.md` 显示为子助手定义。选定已有助手后创建独立助手，继承模型、执行通道、工作区和工具权限，采用插件的角色说明。不会自动选择或回退到其他模型；可在助手设置或管家联系人中使用。
- 本地 MCP 的表单确认请求通过已有对话审批界面交给用户；拒绝、取消不会被当成同意。
- HTTP 可选择自有 OAuth 客户端、Bearer Token 或完整请求头配置。自有 OAuth 支持 PKCE、Client Secret POST/Basic 和固定 loopback 回调；Secret 只保存到加密 Vault。需要服务商允许该客户端注册，不能拿其他宿主的私密配置直接登录。

## 当前兼容边界

支持公开 GitHub 仓库的 `.agents/plugins/marketplace.json` 目录、`.codex-plugin/plugin.json` 清单、Skills 路径、MCP 配置及完整附属文件保存；也识别带 1.0.0 schema 的根目录 `plugin.json`。这与 AIPP 原有的 JavaScript 插件系统是两个入口。

| 组成 | 当前行为 |
| --- | --- |
| Skills、参考资料、示例、资源、脚本 | 保留原文件，扫描技能，按需加载文本；脚本不在安装时执行 |
| 公开 HTTPS MCP + 无认证或公共客户端 OAuth | 复用应用连接与凭据系统；Notion 属于此类 |
| `.app.json` 的 ChatGPT 内部连接器 ID | 保留声明；没有独立 MCP 地址时明确不可连接 |
| 自有 OAuth 客户端、固定回调 | 支持 POST/Basic Secret 与固定 loopback 地址；需要自己的合法注册配置 |
| stdio MCP、请求头与环境变量 | 接入真实启动、工具发现和调用；配置输入经 Vault 保存 |
| commands、子助手定义 | 命令进入调用索引；子助手可按指定模板创建 |
| hooks | 当前固定仓库没有 hooks；未宣称实现仓库外任意 hook 协议 |

具体平台私有依赖和逐包运行条件见 [62 包兼容清单](../agent-plugin-compatibility.md)。标准 MCP 工具调用与 ChatGPT 专属嵌入式组件界面分别验收，不能仅因工具清单出现就宣称界面完全兼容。

62 个固定版本包的解析回归不等于 62 个外部服务的真实账号验收。Windows 真实 Notion 登录、普通模型及原生 Agent 调用仍需在应用中验收；macOS/Linux 也需要实机验证。移动端不提供此安装入口。

## Notion 实机验收

使用测试工作区完成：安装预览 → 授权 → 工具发现 → 选择助手 → 加载一个技能及参考文件 → 搜索并读取一个已知页面。创建页面、更新页面等写操作应使用用户明确指定的测试内容和位置。

继续检查：拒绝授权、重新登录、断开后不可调用、重启状态、两个独立工作区连接、技能更新与回退、本地文件修改保护。不能以模拟 OAuth 测试代替这一验收。

## 卸载与删除连接

已安装插件详情的“更多插件操作”菜单提供“卸载插件”。打开已安装包优先读取本地记录，无须连接 GitHub；确认后删除插件文件和技能，并删除由此包创建的 MCP 连接、工具配置及凭据，复用的已有连接保留。若服务商撤销失败，可明确取消“同时撤销服务商授权”后重试；这不会撤销服务商侧授权。活动进程或本地文件修改仍会阻止卸载并显示原因。

“我的应用”中可删除的连接在详情顶部的“更多连接操作”菜单提供“删除连接”，与卸载整个插件包分开。删除连接沿用现有级联删除与同步机制。内置不可删除工具不显示此按钮。

## 安装状态与目录数量

helper 发布插件介绍、版本、完整技能清单和连接器数量；技能数量由包内容生成，不是手工填写。实际工具数量通过用户连接后的 MCP 工具发现获得，不使用连接器数量冒充工具数量。已安装状态来自本机安装记录。

概览与连接使用同一顶部标题和标签布局。应用详情不重复展示高级管理面板，检查更新仅在已安装后显示。安装任务在应用窗口内共享，关闭详情或切换标签不会丢失正在进行的任务，也不会再次提交安装；失败原因保留到重试。重启应用后以本机安装记录为准，未完成下载不标为已安装。

安装按顺序下载 helper 发布的单插件 ZIP、校验文件摘要与权限、保存插件与安装记录、刷新技能索引。界面显示下载字节数及校验、索引阶段。安装不会自动登录 Notion，服务授权在“连接”中单独完成。helper 单插件包保留依赖解析所需的声明文件，无须下载其他插件的技能和资源。

连接详情的状态在标题下以一行展示；需要处理的状态（继续授权、重新登录、重试断开等）在标题下方直接给出操作，测试连接在标题右侧，重新配置与删除连接在“更多连接操作”菜单中。已有连接默认不重复展开登录表单，凭据存储说明、网络设置与断开连接放在“连接设置”标签。目录应用详情中的插件只负责“配套技能”区块（安装/更新/卸载），连接由详情标题统一发起，安装技能不会自动进入连接流程。

应用目录将连接目录与插件目录合并为同一组“应用与配套技能”，同源应用不重复展示。打开已有单个连接的应用时直接绑定本机连接实例，展示当前状态、工具管理及助手授权；多个连接时先选择工作区，不默认选取第一个账号。

应用卡片、我的应用与详情标题使用 helper 发布的官方图标。发布流程从固定包提取 logo、logoDark 和 composerIcon，按内容摘要托管静态图片并在目录中返回 icon、icon_dark、icon_small；客户端随主题选择浅色/深色图标，缺失或加载失败显示通用图标，不直接访问 GitHub。桌面图片 CSP 仅额外允许 helper 域名。

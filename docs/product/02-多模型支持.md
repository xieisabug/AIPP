# 多模型支持

多模型支持模块允许用户连接和管理多种大语言模型提供商，通过统一的接口进行对话。使用rust-genai来进行支撑该功能的。

---

## LLM 提供商管理

### 提供商配置
- 支持添加多种 LLM 提供商（OpenAI、Anthropic、Google 等主流提供商）
- 每个提供商可配置 API Key、Base URL、API 版本等参数
- 提供商配置持久化到 SQLite 数据库
- 支持多提供商同时启用
- 设置页的提供商表单与 MCP 设置使用一致的细浅色边框。
- 接口地址留空时使用该提供商的默认端点；留空或填写有效地址时不显示额外提示，仅在地址无效时显示错误。
- 非空接口地址 必须是带主机名的 HTTP(S) 基址，不能包含空白、反斜杠、账号密码、查询参数或片段。无效值在字段旁提示，模型列表及对话请求在联网前拒绝，不会回退到默认外部地址。

### OpenCode Go

在提供商列表中选择 **OpenCode Go**，填入 OpenCode Console 的订阅 API Key，获取模型列表并勾选需要的模型，再启用提供商。助手可使用这些模型进行编码对话。模型目录是公开接口，凭据是否有效取决于实际推理请求。

选择模型弹窗只显示模型名称和能力图标。新增模型使用推荐协议，已选模型可在提供商设置中切换协议。Go 文本模型优先使用目录声明的原生协议，菜单将它标为“推荐”。也可显式选择由 OpenCode 网关转换的其他协议。只有一个可用协议时显示只读标签。尚未识别的协议显示“协议待支持”。OpenAI 提供商仍可在 Chat Completions 和 Responses 之间选择。

AIPP 使用同步 UUID 派生 Go 专用的会话标识。续聊、工具回传、重试以及在另一台同步设备继续同一会话时沿用该标识。Go 请求需要持久化会话。如果请求准备阶段失败，聊天会显示失败步骤、模型、会话编号和底层原因。参见 [OpenCode Go 接口文档](https://opencode.ai/v2/docs/console/go/)。

在回复下方打开消息信息，可查看输入和输出 token、首 token 耗时（TTFT）、生成速度（TPS），以及网关返回的本次订阅额度扣减、余额扣费和目录价。对话统计按美元汇总已记录的订阅额度扣减。历史回复只展示已记录的数据。[OpenCode 用量和计费字段](https://opencode.ai/v2/docs/console/api/inference/#cost)

### OpenAI 缓存与会话续接

「网络配置」中的以下选项保留 OpenAI、Responses 标识，桌面端通过字段标题后的问号悬浮显示中文说明，与其他设置字段一致。目前仅对 OpenAI / OpenAI API 类型且使用 Responses 模式的模型生效。

- **OpenAI Responses 提示词缓存标识**：默认开启，为同一会话发送固定缓存标识。旧模型可用它优化缓存路由；GPT-5.6 及后续型号自动路由，标识可用于区分缓存统计。
- **OpenAI 提示词缓存保留时间**：GPT-5.6 及后续型号在 Responses 模式下发送新版 `prompt_cache_options.ttl`，可选「30 分钟（默认）」和「12 小时」，表示最低缓存寿命。缓存写入费分别为普通输入价格的 1.25 倍和 2.5 倍；读取价格不因时长改变。
- **OpenAI 旧版提示词缓存保留策略**：较早模型以及无法识别版本的自定义模型名称沿用 `prompt_cache_retention`，可选「最长 24 小时」和「内存缓存」。GPT-5.5 / GPT-5.5 Pro 仅支持 24 小时；内存缓存通常闲置 5～10 分钟后失效，最长约 1 小时。现有的旧版配置保留，新版时长独立默认 30 分钟，不把旧值 24h 转换为 12h。
- **OpenAI Responses 服务端会话续接**：默认关闭，使用上一轮响应标识，由服务端保存并衔接历史，减少重复上传。需先关闭缓存标识；历史输入仍参与计费。

关闭缓存标识后不发送上述缓存参数。按实际模型代码中的 GPT 版本选择新版或旧版参数，支持带日期后缀和 `openai/` 命名空间的模型代码；服务商须实现对应能力。请求失败会保留原始错误，不会重试切换参数。新版 TTL 无效时在发送请求前明确报错。参见 [OpenAI 官方缓存指南](https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime)。

### 提供商 CRUD
- `add_llm_provider` - 添加新的 LLM 提供商
- `get_llm_providers` - 获取所有已配置的提供商列表
- `get_filtered_providers` - 获取过滤后的提供商列表
- `update_llm_provider` - 更新提供商配置
- `delete_llm_provider` - 删除提供商
- `export_llm_provider` - 导出 LLM 提供商
- `import_llm_provider` - 导入 LLM 提供商

### 提供商配置
- `get_llm_provider_config` - 获取 LLM 提供商配置
- `update_llm_provider_config` - 更新 LLM 提供商配置

## 模型配置

### 模型管理
- 支持为每个提供商添加多个模型
- 每个模型可配置独立参数：
  - `max_tokens` - 最大 Token 数
  - `temperature` - 温度参数
  - `top_p` - Top-p 采样
  - 其他模型特定参数

### 模型分类
- 按提供商分组显示
- 模型与提供商关联存储
- 支持启用/禁用单个模型

### 模型 CRUD
- `add_llm_model` - 添加新模型
- `get_llm_models` - 获取模型列表
- `update_llm_model` - 更新模型配置
- `delete_llm_model` - 删除模型
- `get_models_for_select` - 获取用于选择的模型
- `get_filtered_models_for_select` - 获取过滤后的用于选择的模型

### 模型列表获取
- `fetch_model_list` - 从提供商获取模型列表
- `preview_model_list` - 预览模型列表
- `update_selected_models` - 更新选中的模型

---

## 模型切换

### 对话内切换
- 支持在对话中切换模型
- 切换后新消息使用新模型
- 历史消息保留原模型信息

### 对话独立配置
- 不同对话可以使用不同模型
- 对话创建时绑定当前选择的模型

### 无模型回退策略
- 当配置的模型不存在时，禁止自动回退到其他模型
- 直接返回错误信息，在界面上提示用户检查配置
- 确保用户明确知道配置问题所在

## genai 客户端集成

### 自定义 genai 客户端
- 基于自定义 fork 的 genai 库
- 支持多种模型提供商统一封装
- 流式聊天支持
- 工具调用支持

### ChatRequest 构建
- 系统提示词合并
- 消息历史构建
- 工具配置合并
- ChatOptions 构建（temperature、max_tokens 等）

### 流式响应处理
- ChatStreamEvent 事件流
- Token 计数
- 工具调用检测
- 错误处理与重试

---

## 配置合并

### 配置优先级
- 助手模型配置优先级高于提供商默认配置
- 支持按场景配置覆盖
- 最终合并后的配置传递给 genai 客户端

### 配置验证
- 验证模型是否存在
- 验证提供商配置有效性
- 无回退，缺失直接报错

## Provider 分享

### 加密分享
- 支持将 LLM 提供商配置导出为加密分享码
- 使用 AES-256-GCM 加密保护 API Key 等敏感信息
- 分享码通过 gzip 压缩 + Base64 编码生成
- 导入时需要输入密码解密

### 分享流程
- `export_llm_provider` 导出提供商配置为分享码
- `import_llm_provider` 通过分享码导入提供商配置
- `ShareDialog.tsx` 分享对话框 UI
- 一键复制分享码到剪贴板

## 删除与刷新

- 删除提供商会清理所属模型、提供商配置及请求模式偏好；助手模型槽位保留为未绑定状态，不会自动选择其他模型。历史消息保留，并解除模型 ID 引用。
- 单独删除模型会同时删除其请求模式偏好。刷新或重选模型列表时保留仍存在模型的 ID 和有效偏好，只清理被移除模型的关联数据。

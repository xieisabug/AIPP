# 插件系统

插件系统允许开发者以最小侵入的方式扩展 AIPP 的功能，支持新增助手类型、注入界面组件、扩展后台逻辑等。

---

## 插件类型

### AssistantType (1)
- **助手类型插件** - 在「个人助手配置」页面注册并渲染新的助手类型
- 当前已实现，可直接使用
- 用于扩展不同类型的 AI 助手（如代码生成、学术写作等）

### InterfaceType (2)
- **界面插件** - 渲染独立窗口或嵌入式 UI
- 预留接口，即将支持
- 用于添加自定义 UI 组件和窗口

### ApplicationType (3)
- **应用插件** - 脱离 UI、提供后台能力
- 预留接口，即将支持
- 用于后台服务和定时任务等

## 插件生命周期

### onPluginLoad
- 插件加载完成后调用
- 可用于初始化插件状态
- 传入 `systemApi` 系统 API 对象

### config
- 返回插件配置信息
- 声明插件名称、类型等元数据
- 框架据此判断插件类型和能力

### onAssistantTypeInit
- 助手类型初始化时调用
- 注册助手类型和表单字段
- 传入 `assistantTypeApi` API 对象

### onAssistantTypeSelect
- 用户在下拉框选中该助手类型时触发
- 可设置默认值、隐藏字段等
- 传入 `assistantTypeApi` API 对象

### onAssistantTypeRun
- 点击「运行」后触发
- 实现助手的具体运行逻辑
- 传入 `assistantRunApi` API 对象

### contributions.views + renderView
- 插件界面统一通过 `plugin.json` 的 `contributions.views` 声明
- 插件实例通过 `renderView(viewId, context?)` 返回对应 React 组件
- 插件中心使用 `location: "config.plugin-center"` 渲染插件管理页界面

### renderAction
- 在宿主预留的 action 插槽渲染轻量操作按钮
- 当前已支持 `conversation.title-actions`
- 适合“标题栏按钮 + Dialog”这类小交互

### contributions.slots + renderSlot
- 插件可在宿主预留的 UI slot 中替换局部视觉节点
- 当前已支持 `chat.input.send-button-visual`，用于替换 Chat UI 与总管家输入区发送按钮完整视觉层
- 也支持 `chat.input.send-button-icon`，用于仅替换默认箭头/停止方块图标
- 宿主保留按钮点击、发送/停止、布局和禁用态；插件只返回视觉节点
- `renderSlot(slotId, context)` 的上下文包含 `conversationId`、`assistantId`、`isResponding`、`inputText`、`fileCount`、`isMobile`、`windowLabel` 等信息

### MCP 工具调用组件
- 插件可通过 `systemApi.registerMcpToolComponent()` 注册聊天中的 MCP 工具调用视觉组件
- 注册需要在插件权限中声明 `mcp.tool-component.register`
- 组件可通过 `match` 绑定到指定 `serverName`、`toolName`，未匹配时仍回退到宿主默认工具调用组件
- 用户可在「设置 → 显示 → MCP工具调用组件」选择自动匹配、默认组件或已注册组件
- 自动匹配模式会按 `priority` 优先选择匹配当前工具调用的组件；选择具体组件时仍要求该组件的 `match` 能匹配当前调用
- 组件 `render(props)` 会收到当前工具调用上下文，稳定入口是 `props.currentToolCall`，其中包含 `call_id`、`conversation_id`、`message_id`、`status`、`llm_call_id`、`server_name`、`tool_name`、`parameters`、`result`、`error`、`started_time`、`finished_time` 等字段
- 为兼容轻量渲染，`props` 也保留散字段：`serverName`、`toolName`、`parameters`、`status`、`error`、`conversationId`、`messageId`、`callId`、`isStreaming`、`isLastCall` 等

示例：

```ts
systemApi.registerMcpToolComponent({
  id: "demo.load-tool-card",
  label: "加载工具卡片",
  match: [{ toolName: "load_mcp_tool" }],
  priority: 200,
  render: (props) => {
    const call = props.currentToolCall;
    return (
      <div>
        <strong>{props.toolName}</strong>
        <span>{call?.status ?? props.status}</span>
        {call?.error ? <pre>{call.error}</pre> : null}
      </div>
    );
  },
});
```

## 助手类型插件开发

### 助手类型注册
- `assistantTypeApi.typeRegist()` 注册新助手类型
- 指定类型 ID、名称、插件实例
- 类型 ID 避免与现有重复

### 动态表单字段添加
- `assistantTypeApi.addField()` 添加表单字段
- 配置字段名称、标签、类型
- 设置字段位置（header/body）和提示信息

### 字段隐藏/显示控制
- `assistantTypeApi.hideField()` 隐藏字段
- `assistantTypeApi.showField()` 显示字段
- 可在 `onAssistantTypeSelect` 中动态控制

### 字段默认值设置
- `assistantTypeApi.forceFieldValue()` 强制设置字段值
- 常用于助手类型切换时设置默认参数

### 子任务注册
- `assistantTypeApi.subTaskRegist()` 注册子任务
- 配置子任务编码、名称、描述、系统提示词
- 可选配置 `iconComponent` 图标组件

### 助手运行逻辑实现
- `assistantRunApi.getUserInput()` 获取用户输入
- `assistantRunApi.askAI()` 调用 AI
- `assistantRunApi.askAssistant()` 调用其他助手
- `assistantRunApi.appendAiResponse()` 追加 AI 响应

## 插件加载机制

> **注意**: 插件系统的核心逻辑在前端实现（`src/plugins/`），后端 `src-tauri/src/plugin/mod.rs` 为空模块，仅提供数据库存储支持（`plugin_db.rs`）。插件的加载、生命周期管理和 API 注入均由前端 JavaScript 完成。

### 插件目录结构
```
<AppDataDir>/plugin/<plugin_code>/
  └─ dist/
     └─ main.js  # 产物入口，必须导出全局插件类
```

### 插件中心安装
- 插件中心支持从官方推荐源、GitHub 仓库、ZIP 链接或本地 ZIP 安装插件
- 官方推荐插件可逐项并行安装，每个插件会独立显示安装中、已完成或失败状态
- 推荐插件安装失败后，可在对应插件卡片内直接重试，或使用网络设置中的代理重试
- 官方推荐插件卡片提供“前往仓库”入口，可在浏览器中打开对应仓库
- GitHub / ZIP 手动来源会直接执行安装；安装失败时支持按原请求直接重试或切换代理重试

### 插件脚本动态加载
- ConfigWindow 和 PluginWindow 运行时注入 `<script>` 标签
- 脚本路径指向插件的 `main.js`
- Tauri 提供跨平台自动定位 AppDataDir

### 全局插件类挂载
- 插件类必须挂载到 `window` 全局对象
- 例如：`window.SamplePlugin = MyPlugin`
- 全局名称需与加载列表保持一致

### 插件 API 注入
- 加载完成后框架查找插件类
- 实例化插件并触发生命周期函数
- 注入相应的 API 对象（systemApi、assistantTypeApi 等）

### 标题栏 Action 注入
- 插件可在 `plugin.json` 的 `contributions.actions` 中声明 action
- 宿主当前支持 `conversation.title-actions`
- 运行期通过 `renderAction(actionId, context)` 渲染按钮，`context` 会携带当前 `conversationId`、`assistantId`、会话名和助手名

### 输入区发送按钮图标注入
- 插件可在 `plugin.json` 的 `contributions.slots` 中声明 `location: "chat.input.send-button-visual"` 来替换整个按钮视觉层
- 插件也可声明 `location: "chat.input.send-button-icon"` 仅替换内置图标
- 运行期通过 `renderSlot(slotId, context)` 返回发送按钮视觉节点
- 插件本地图片资源可通过 `systemApi.assetUrl("assets/send-leaf.svg")` 转换为窗口可加载 URL

### 受限助手 / 会话 API
- `systemApi.conversations.getWithMessages(conversationId)`：读取当前对话与消息
- `systemApi.assistants.getDetail(assistantId)`：读取助手详情与当前 prompt
- `systemApi.assistants.updatePrompt(...)`：在用户确认后安全更新助手 prompt
- `systemApi.assetUrl(relativePath)`：引用当前插件目录内的图片等静态资源
- 建议优先使用这些 API，而不是插件内直接 `invoke(...)` 调宿主命令

## 子任务图标

### 图标组件注册
- 注册子任务时可传入 `iconComponent`
- 支持两种类型：
  - `React.ReactNode` - 直接渲染的节点
  - `React.ComponentType` - 组件类型（如 lucide-react 图标）

### 图标渲染
- 框架按 `code` 注册到运行期前端注册表
- UI 在子任务选择/详情处显示图标
- lucide-react 图标支持 size、className 等属性

### 示例
```tsx
import { Wrench } from 'lucide-react';

// 使用组件类型
iconComponent: Wrench

// 或使用直接渲染的节点
iconComponent: <Wrench className="h-4 w-4" />
```

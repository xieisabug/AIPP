# 定时任务

让助手按时提醒、定期检查、周期性汇报。到点后，执行助手在一个全新的会话里完成指令，再以自己的身份把结果发给你。

设计与取舍见 [定时任务系统重设计 PRD](../scheduled-task-redesign-prd.md)。

---

## 怎么创建

- **在聊天里说**：例如「每周四下午 4 点提醒我今天休息」「工作日每天 9 点帮我看一下 X 有没有更新，有变化再告诉我」。助手用 `schedule_task` 工具创建，创建即生效，不再额外确认；回复里会告诉你执行时间和接下来几次的运行时间。
- **在定时任务窗口新建**：填写名称、执行助手、时间、指令、结果发到哪、什么时候发。

管家模式下所有助手（总管家、联系人、受托任务、群成员）都能创建和管理定时任务；普通聊天里，助手启用了 Agent 工具也能创建。

## 时间怎么写

时间是一个字符串，按本机时区解释：

| 写法 | 示例 |
|---|---|
| 一次性 | `2026-11-13T16:00+08:00`、`2026-11-13 16:00`、`in 30m` |
| 固定间隔 | `every 30m`、`every 2h`、`every 1d at 09:00`、`every 2w at 16:00` |
| 5 段 cron（分 时 日 月 周） | `0 16 * * 4`（每周四 16:00）、`0 9 * * 1-5`（工作日 9 点）、`0 9 1,15 * *`（每月 1、15 号 9 点） |

窗口的表单提供「一次 / 每天 / 每周 / 每月 / 间隔 / 高级」几种方式，下方实时显示人话描述和接下来 3 次运行时间。

可选的结束条件：截止日期、最多运行次数；一次性任务运行后自动结束。

## 运行时发生什么

1. 到点后，先登记这次运行并推进下一次时间，再做检查。之后的任何问题都只会让这条记录结束为「跳过」或「失败」并写明原因，不会反复重试同一时段。
2. 执行助手在一个隐藏的运行会话里工作，看不到之前的聊天，所以指令要写清背景、偏好、要做什么、什么情况值得告诉你。上一次运行的结果会自动附带给它，便于「有变化才告诉我」。
3. 管家模式创建的任务使用与总管家一致的工具基线（全局启用的 MCP 与 Skills、SuperAdmin），运行中不能向你提问、不能创建或删除其他定时任务，只能暂停或修改它自己。
4. 结果以执行助手的身份发出：
   - 默认发到**执行助手的管家私聊**（总管家即主会话；你重开私聊后会自动发到新的那条）；
   - 普通聊天里创建的任务发回**创建它的会话**；
   - 窗口里也可以选**单独的会话**，结果出现在聊天列表里。
   定时结果关联本次任务运行和触发消息，不改变投递会话当前的工作目标，也不使正在进行的回复失效；收到结果后可在原会话继续追问。
   消息上标有「来自定时任务《X》」，点击打开该任务；没开窗口时会有系统通知。
5. 「什么时候发」：**每次都发**（提醒）、**有新内容才发**（检查、监控：没有值得说的内容时助手只回复 `[NO_REPLY]`，这次不打扰你）、**只记录**。

## 无人值守时的安全

运行时你不在场，每个工具调用按副作用处理：

- 读取、查询等免审核工具直接执行；
- 其他调用交给审核模型，审核时附带任务指令作为「用户意图」：明确符合指令的操作（比如发到指令里指定的群）会放行；
- 审核没通过的操作不挂起，而是交给**总管家裁决**：总管家主会话收到一条 `<scheduled_task_approval>`，结合任务指令和它掌握的上下文允许或拒绝（15 分钟内未裁决按拒绝）；没有总管家时直接拒绝；
- `rm`/删除类命令、需要用户批准的 SuperAdmin 动作一律不执行，结果里会写明需要你亲自处理。

被拒绝的操作会作为工具结果交给助手，它会在最终回复里说明卡在哪一步。审核记录在运行会话的工具调用上可以看到，总管家的裁决记为 `butler_allow` / `butler_deny`。

普通聊天的工具审核同样附带用户最近的请求作为意图。管家模式下所有助手统一使用模型审核。

## 运行记录

每次到点都会留下一条记录：

| 状态 | 含义 |
|---|---|
| 运行中 | 正在执行 |
| 已发送 | 完成并已发给你 |
| 无新内容 | 完成，没有值得说的（或设置为只记录） |
| 失败 | 执行失败，附具体原因（含模型调用失败、超时、发送失败） |
| 跳过 | 没有开始，附原因（执行助手已删除、模型未配置、上一次还没结束等） |
| 错过 | 应用没开，错过了这次 |
| 已停止 | 你手动停止 |

- **应用没开时**：默认只补跑最近一次（运行提示里会说明晚了多久），更早错过的时段记为「错过」；也可以设置为只记录不补跑。移动端启动前错过的时段只记录。
- **连续失败**：2 次时在投递会话里提醒你原因；5 次自动暂停，任务列表出现在「需要处理」。修好后打开「启用」即可恢复，暂停期间的时段不补跑。
- 模型接口临时出错时，本次运行内按 30 秒、2 分钟、5 分钟重试。
- 同一时刻最多同时运行 3 个任务。

## 定时任务窗口

- 左侧按「需要处理 / 已启用 / 已暂停 / 已结束」分组，可搜索名称、助手或指令；每行显示上次结果、人话时间和下次运行。
- 详情：时间与接下来 3 次、执行助手、结果发到、什么时候发、已运行次数与结束条件、暂停原因；指令；运行记录与所选运行的产出和过程（工具调用、审核、总管家裁决、发送）。
- 操作：启用/暂停、立即运行（不改变计划时间）、停止、编辑、删除。

## 移动端

「本机任务」页列出定时任务、运行记录，可在本机运行一次或停止本机运行。任务只在创建它的设备上运行，定时任务数据不参与同步。

## 旧任务

升级后旧任务自动转换为新的时间写法：管家绑定的任务改为发到执行助手的私聊，原来的「通知判定规则」并入指令，按「有新内容才发」处理；无法精确表达的（如「每 2 周的周一和周四」）会暂停并提示确认时间。升级前错过的时段不补跑。原「管家后台检查范围」已移除。

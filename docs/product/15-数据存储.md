# 数据存储

数据存储模块以多个独立的 SQLite 数据库作为本地主存储，同时支持“本地模式 / 自建同步”两种运行方式。

---

## SQLite 本地存储

### 本地主存储
- 本地优先的设计理念
- 所有数据存储在用户设备上
- 保护用户隐私

### 自建同步
- 可连接用户自建的 AIPP sync-server
- 同步核心业务数据（LLM 提供商/模型、助手、MCP 服务器等），不同步本机密钥、运行态和本地路径
- 同步配置与 token 分离存储，token 使用 AES-256-GCM 加密存储；主密钥保存在 OS keychain（Windows 凭据管理器 / macOS Keychain / Linux Secret Service），keychain 不可用时回退为本地文件存储
- `llm_provider_config` 按白名单同步已知安全配置项（endpoint、ACP 命令与参数等），api_key 及 env 类配置不上传
- 本地删除会同步上传 delete 事件，多端数据收敛一致。新建后从未尝试上传即删除的对象会取消上传；已经尝试上传的对象保留原事件并按顺序补发删除，旧上传回声不会恢复已删除的消息或配置。
- 请求结果未知时保留原事件身份和内容，并持续退避重试；同对象后续编辑等待原事件确认后再上传，避免旧回执覆盖新编辑。下载到本机原上传事件也会作为回执处理。
- 接收业务数据、同步身份与确认记录采用可恢复的跨库提交；中断后先恢复未完成的元数据，再继续扫描和应用，避免重放插入重复数据。
- 模型代码、配置键等包含特殊字符或过长时使用稳定且有长度上限的同步身份；已发布的合法身份保持兼容。非法事件单独显示失败，服务端逐条校验；有效邻居事件可以继续上传。
- 双端同时修改同一对象时以服务器版本为准（远端赢），客户端会提示冲突已按服务器版本解决
- 同一会话只有在同一父节点/生成组下存在尚未确认的本地兄弟分支时才自动分叉；下载历史重新生成版本、重复拉取、无关分支等待上传或历史响应未完成不会触发分叉。同一远端分支的后续消息沿用已有分叉。已有历史分叉不会自动合并。
- 冲突提示在一轮同步结束后汇总一次，打开设置不会重复提示历史冲突；重复状态读取错误显示在状态区。
- “无法应用”会展开显示数量最多的五类具体原因和示例对象 ID。依赖补齐后可点“重试无法应用的变更”；若仍有未解决项，会显示剩余数量。缺少所属会话的历史消息变更会保留，不能凭空恢复或自动归入其他会话。
- 上传优先发送供应商、模型、助手等父对象，再发送依赖它们的会话、消息和附件；接收端按依赖顺序应用并自动重试跨页依赖。源设备已删除的可选历史引用会清空，必需归属缺失仍会阻止上传。若父对象从未上传，单靠重试无法恢复，需要来源设备升级后重新发送有效快照。
- 模型绑定及总结、总管家等配置中的供应商引用会转换为目标设备 ID；未绑定模型参数兼容旧空值。两端均需升级以发送完整引用，旧变更缺少身份时会提示来源设备重新同步，不会自动换用其他模型。
- 新设备的快速使用助手初始化时带有空模型占位；同步收到明确的模型绑定后，助手读取会忽略该空占位，保留所有实际配置的模型。指定模型不存在仍会报错，需要检查配置。
- 快速使用助手收到自定义提示词后，读取时忽略初始化默认提示词，原始记录仍保留用于同步重放。多条自定义提示词仍会保留，当前没有自动裁定两端不同配置的规则。
- 助手模型绑定以及供应商所属的模型、配置和请求模式必须等待供应商到达，不能把来源设备数字 ID 当成本机供应商，也不能将必要供应商引用置空。官方供应商的同步身份与本机行号分离，导入时不会覆盖同号的其他供应商。
- 重置同步从头读取当前服务器的事件，保留对象身份、已确认版本、分支路由和待上传事件，避免同一历史重新生成 UUID。它不负责合并已上传的重复会话。
- 本地与远端均有数据而本机没有已确认同步基线时，会停止上传并提示先备份、使用空数据目录从远端恢复，或恢复与业务库配套的 sync.db；不能把两份旧库直接当作首次同步合并。若本机保留了在同服务器、同账号空库上开始首次上传的持久化记录，会先重放已尝试事件以找回丢失回执，确认前不扫描或上传新的编辑。
- 远端游标低于本机已确认历史，或远端为空而本机有旧回执时，会停止同步，要求先备份核验。该检查能检测游标回退；当前协议没有服务器历史代号，不能保证识别已经增长超过旧游标的重建服务。
- 如果历史服务端遗漏了助手或供应商主记录，需要从带原 UUID 的可靠备份补回，重放子记录无法凭空补出名称、类型和配置。维护工具 `sync_assistant_recovery` 使用正常客户端的应用、依赖排序及摘要代码，将完整服务端事件快照重放到新建副本；它不联网、不安装到正在使用的配置目录，也不推进其他领域的同步游标。密钥和本机命令等配置需要在设备本地单独恢复或重新配置。
- 更换服务器地址或 token 导致账号范围待确认时，不允许通过重置直接合并已有数据；请先备份并使用独立数据目录连接，避免把旧账号的版本状态用于新账号。
- 服务器地址使用 http:// 时，设置页在地址输入框下方用一行小字提示明文传输风险
- 远端拉取、冲突处理或无法应用变更重试成功后，自动刷新聊天列表、当前聊天与 Todo、助手、MCP、模型提供商、功能配置和 Artifact 收藏。聊天列表保留已加载范围与当前选择；当前会话被删除时切换到其他会话。
- 本机正在生成回复时，聊天列表立即刷新，正文等待回复结束后更新，输入草稿保留。设置和收藏编辑表单直接显示同步后的内容，尚未保存的输入会被覆盖。

同步故障修复需要更新所有参与设备。只重新部署服务端不会修复客户端的分叉判断、补出缺失对象或合并历史分叉。测试数据可丢弃时，先暂停所有设备同步，使用独立的新账号（同账号换 token 不隔离数据），或停止服务并清空专用测试服务的数据；各测试设备再清空旧测试业务数据与同步状态。仅在一台设备建立干净测试数据并完成首次上传，再让其余空设备加入，避免旧设备重新上传问题数据。

### 分离的 SQLite 数据库
- 使用多个独立的 SQLite 数据库文件
- 按功能域分离数据库，便于管理和维护
- rusqlite 库提供 Rust 绑定
- 事务支持，数据一致性保证

### rusqlite ORM
- `db/mod.rs` 数据库主模块
- Repository 模式封装 CRUD 操作
- 类型安全的数据访问
- 连接池管理

### 数据库迁移管理
- 迁移脚本版本管理
- 自动迁移检测和执行
- 向下兼容性保证
- 迁移失败回滚

## 主要数据表说明

### conversation - 对话记录
- 对话基本信息（ID、名称、创建时间等）
- 关联的助手 ID
- 对话列表查询
- 对话创建、更新、删除

### message - 消息记录（支持版本化）
- 消息内容和类型
- generation_group_id 和 parent_group_id 版本管理
- Token 计数（input/output/total）
- 时间戳（开始、完成、首 Token 时间）
- 工具调用 JSON
- 消息附件关联

### message_attachment - 消息附件
- 附件关联的消息 ID
- 附件类型（Image, Text, PDF, Word, PowerPoint, Excel）
- 附件元数据
- 文件路径或内容

### assistant - 助手配置
- 助手名称和描述
- 助手类型（0=普通对话, 1=多模型对比, 2=工作流, 3=展示, 4=ACP 助手）
- 系统提示词
- 助手配置 JSON
- 助手模型关联

### llm_provider - LLM 提供商
- 提供商名称和类型
- Base URL 和非密钥配置
- 提供商配置
- 启用/禁用状态

### llm_model - LLM 模型
- 模型名称和代码
- 关联的提供商 ID
- 模型参数（max_tokens、temperature 等）
- 模型配置 JSON
- 启用/禁用状态

### mcp_server - MCP 服务器配置
- 服务器名称
- 命令和工作目录
- 环境变量和附加参数
- 服务器配置 JSON

### conversation_todo - 对话 Todo
- Todo 任务关联对话
- Todo 内容和状态
- 任务创建和更新

## 数据隐私

### 本地存储优先
- 所有数据存储在本地 SQLite 文件
- 本地模式下不启用同步；设置页只保留同步模式选择，不展示连接状态、同步队列、上次同步、错误、无法应用、失效引用，以及自动同步、重试、清理和重置操作
- 自建同步模式由用户主动连接自己的服务器
- 用户完全控制数据
- 数据不离开用户设备

### 无遥测功能
- 不收集用户使用数据
- 不发送任何分析数据
- 完全透明的代码
- 隐私优先设计

### 用户数据完全掌控
- 用户可以备份数据库文件
- 用户可以删除所有数据
- 数据格式开放
- 无数据锁定

## 数据库模块架构

### Repository 模式
- 每个实体有独立的 Repository
- ConversationRepository、MessageRepository 等
- 统一的 CRUD 接口
- 类型安全的数据访问

### 级联删除
- 界面、定时清理、内置管理工具和同步删除复用数据层清理规则；跨库关联在同一 SQLite 连接的事务中处理，任一步执行失败回滚并保留具体错误。
- 显式按归属顺序删除，不要求旧表结构具备级联外键；本次修复不自动扫描或删除存量孤立数据。
- 工作区目录、技能原文件、附件原文件和独立制品数据库不随关联记录自动删除。
- 总管家主对话没有新增删除入口；“重开新会话”继续归档旧主对话并迁移任务，不删除历史。

### 测试隔离
- 测试使用内存数据库
- `Connection::open_in_memory()` 创建测试数据库
- 测试之间完全隔离
- 不影响真实数据

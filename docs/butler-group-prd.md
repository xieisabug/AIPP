# 管家群聊 PRD

需求：#284（群与上下文）、#282（发言调度）。第一版“协作群”要求用户手动选择接收成员和讨论模式，并把大量调度字段塞进成员输入，不符合聊天软件的使用习惯，已整体重写为本版本。

## 产品定位

群聊就是管家联系人列表里的一个“群”：用户把几位助手（可包括总管家）拉进群，在群里直接说话，由合适的成员回复。用户不需要选择“和谁说”，也不需要选择“大家一起答 / 一个个答 / 独立判断”这类模式。

范围限于桌面管家；不包含外部渠道接入和多真人账号。

## 入口与界面

- 联系人列表顶部的“发起群聊”按钮：勾选助手（默认勾选总管家），群名可不填（默认用成员名拼接）。至少两位成员。
- 群聊和联系人显示在同一个列表里：群头像拼接成员头像，摘要显示最后一条消息或“某某 正在输入…”，有未读时显示圆点。右键可删除群聊。
- 点击群聊在主区域打开，不弹新窗口。界面只有聊天内容：
  - 用户消息在右侧；成员消息在左侧，带头像和名字，正文按 Markdown 渲染；系统提示（邀请、移出、停止、失败）居中显示。
  - 成员回复期间显示“正在输入”，有辅助模型时附带一句进展。
  - 成员需要用户回答问题时，问题卡片直接出现在群聊里；审批沿用管家窗口的审批弹窗。
  - 消息使用与私聊相同的消息组件：Markdown、代码预览/运行、悬停操作条与右键菜单（复制、消息信息、导出、引用回复）一致。成员发言指向其执行会话中的那条最终回复，消息信息与代码运行落在该会话上。引用沿用私聊的引用按钮、输入框引用标签和已发送消息上的引用标签。
  - 输入框输入 `@` 弹出成员列表，可选“所有人”。
  - 有回复进行中时，发送按钮旁出现“停止”。
- 点击顶部群名打开“群聊信息”：改群名、查看成员、邀请成员、移出成员、删除群聊。
- 不展示收件箱状态、席位、投递包、序号等内部信息。

## 谁来回复

按顺序判断，前面命中就不再往下：

1. 消息里 `@成员名`：被点名的成员回复；`@所有人` 表示全部成员。点了多位成员时，由调度判断是否需要多轮讨论。
2. 引用了某位成员的消息：原作者回复。
3. 群里只有一位成员：由该成员回复。
4. 其他情况：由调度模型判断。优先使用管家设置里的“小型辅助模型”，未配置时使用总管家模型。调度只输出发言名单和讨论轮数，不回答问题：叫到名字的选被叫的人；“大家说说”选全部；接着某位成员的话题就选那位；否则选最合适的一位，必要时最多三位；拿不准时选总管家。

调度模型配置无效或调用失败时，群里显示具体失败原因，不换用其他模型。

多位成员回复时同时开始，界面上一起显示“正在输入”。各自看不到别人正在写的内容，下一次轮到他们时会补上别人的回复。

用户要求成员讨论（讨论、商量、辩论、互相评审、讨论出结论等）时，调度给出讨论轮数（默认 3 轮，用户指定时照用户说的，最多 5 轮）。每轮所有人说完后带着彼此的新发言进入下一轮：第一轮亮观点，中间轮针对别人的具体观点回应，最后一轮收敛结论；没有新内容的成员不发言。一轮里没人再发言、到达轮数、用户插话或点“停止”时讨论结束。界面顶部显示“讨论中 · 第 N/M 轮”。

成员在回复里 `@其他成员` 会请对方接着回复；讨论还有下一轮时，被 @ 的参与者在下一轮回应。成员之间连续接力最多 3 层、同一条用户消息最多引出 12 次接力，超过时群里提示，用户可以直接 @ 对方。

## 上下文

- 每位成员在每个群里有独立的执行会话，与私聊、其他群互不相通。
- 轮到成员回复时，把它上次回复后群里其他人的发言整理成普通聊天记录发给它，例如：
  ```
  群聊「周报小组」的新消息：

  用户：帮我写本周周报
  写作助手：初稿如下……
  ```
  成员自己说过的话不会重复发送；系统提示中写给用户的“你”会改写成“用户”。过长的积压只展开最近的消息，并注明省略数量。
- 新成员只看到加入之后的消息。
- 群规则写在成员会话的系统提示里；当前成员名单、本轮情况（谁在同时回复、讨论第几轮）和说话方式提醒每轮随输入提供，不写进历史，规则调整前加入的成员也能生效。

## 说话方式

成员在群里要像同事在工作群里聊天，参考 Claude 系统提示的对话格式要求（闲聊简短、用段落不用列表、列举用自然语言）和中文“去 AI 味”改稿规则（删除无内容的招呼、预告、致谢与提示语，同一件事不说两遍）：

- 多数回复一两段、每段两三句，先说结论或态度。
- 分段说，一个意思一段。
- 不把观点拆成 1、2、3 逐条展开，不加标题和成片加粗；用户要清单、步骤或对比表时除外。
- 只说最要紧的一两点；不客套、不预告、不总结全场、不重复别人。
- 有自己的立场，同意就补充新理由，不同意就直说。
- 报告、方案、代码、文件照常完整产出，群里只说结论和产物位置。
- 成员在群里保留管理工具与提问能力，但不提供联系人协作工具；群内协作通过 @ 完成。工具调用和执行过程只在成员自己的会话里。

## 回复、停止与异常

- 每位成员一次只处理一项回复；被触发的消息已经在更早的回复里送达时不再重复回复。
- 成员的最终回复以其名义发到群里；最终回复为 `[[NO_REPLY]]` 时不发言。
- 回复失败（认证、模型、通道等）在群里显示“某某 没能回复：具体原因”；执行结束却没有最终回复时，空闲一段时间后同样提示，不自动重试。
- “停止”取消排队中的回复、打断进行中的执行；停止或移出后迟到的结果不会再发到群里。
- 应用重启后，已经完成的回复照常发出，未完成的回复提示结果无法确认，不自动重做。
- 关闭管家只阻止新的回复，已经开始的回复照常结算。
- 删除群聊会先停止进行中的回复，再删除群消息和成员在本群的执行会话；私聊不受影响。助手被删除后自动移出群聊。

## 验收

1. 群聊出现在联系人列表中，点击后在主区域打开，没有接收人与模式选择。
2. 不 @ 任何人时由合适的成员回复；@ 某人只由其回复；@所有人 时大家同时回复，之后的回复能看到彼此。
3. 要求讨论时进行多轮，每轮回应他人观点，没人有新内容或到达轮数后结束，用户插话即停止续轮。
4. 引用成员消息时由原作者回复。
5. 成员回复中 @ 其他成员会触发对方回复，接力受层数与次数限制。
6. 成员会话里的用户消息是可读的聊天记录，不含调度字段；私聊与其他群内容不会进入。
7. 成员说话简短、分段、不逐条列点。
8. 成员提问在群里显示并能回答；审批弹窗正常出现。
9. 停止后不再有新回复；迟到结果不显示。
10. 调度或回复失败时群里有具体原因。
11. 重启后已完成的回复显示一次，未完成的不自动重做。
12. 旧版协作群的群、成员和公开消息迁移后可继续使用。

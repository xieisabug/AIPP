# 飞书工具状态展示设计文档 v2

## 概述

本文档定义 AIPP 在飞书外部渠道中，对每个内置工具的调用和结果消息的展示规范。核心原则：**每个工具都有自己独特的展示格式**，不使用通用的"正在执行"包装，工具输出必须与普通文本在视觉上有明确区分。

## 技术约束

### 数据流

1. **工具调用**（assistant 消息内嵌 `<!-- MCP_TOOL_CALL:{...} -->`）→ `present_call()` 渲染
2. **工具结果**（`tool_result` 消息，格式为 `Tool execution completed:\n\nTool Call ID: ...\nTool: ...\nServer: ...\nParameters: ...\nResult:\n...`）→ `present_result()` 渲染

### 关键限制

- **metadata 不保留**：`execute_builtin_tool` 序列化时只保留 `content` 数组，`metadata`（含 `exit_code`、`file_path`、`bash_id` 等）被丢弃
- **content 数组格式**：`[{"type":"text","text":"..."}]` 或 `[{"type":"json","json":{...}}]`
- **server_name 为中文显示名**：`Agent 工具`、`操作工具`、`UI交互工具`、`搜索工具`、`Artifact 工作区工具`
- **渲染结果为纯 Markdown 文本**：飞书通过 `send_markdown_message_to_target()` 发送，会尝试构建为 Markdown 卡片

## 全局展示规则

### 工具调用展示（assistant 消息）

当 assistant 消息同时包含文本和工具调用时，格式为：

```
{assistant 文本}

{工具调用1的展示}
{工具调用2的展示}
```

每个工具调用使用**自带图标前缀**的独立行，不使用"正在执行"统一包装，不使用无序列表 `- ` 格式。

### 工具结果展示（tool_result 消息）

结果消息独立发送，使用 **Markdown 结构化格式**，包含标题行和详情行。成功用 ✅，失败用 ❌，部分成功用 ⚠️。

### 兜底规则

未被任何 Presenter 匹配的工具，使用 FallbackToolPresenter：
- 调用：`🔧 {server}/{tool_name}`
- 结果成功：`✅ {server}/{tool_name} 执行完成`（附内容摘要）
- 结果失败：`❌ {server}/{tool_name} 执行失败`（附错误摘要）

## 逐工具展示设计

### 1. `todo_write`（Agent 工具）

最重要的工具之一。必须展示完整任务清单和每个任务的当前状态。

**参数结构**：
```json
{
  "todos": [
    {"content": "任务标题", "status": "pending|in_progress|completed|blocked", "activeForm": "当前执行描述"}
  ]
}
```

**结果 content**：`[{"type":"text","text":"Todo list updated: 1/3 tasks completed (33%)\n\nCurrent task: 创建脚本"}]`

#### 调用展示

```
📋 任务列表更新（{total} 项，{completed} 完成）

✅ 已完成的任务标题
⏳ 进行中的任务标题 → 当前执行描述
⬜ 待办的任务标题
🚫 已阻塞的任务标题
```

注意：
- 状态图标含义：✅ completed、⏳ in_progress、⬜ pending、🚫 blocked
- 如果 `activeForm` 与 `content` 不同，用 `→` 连接显示当前执行描述
- 总是从 `parameters.todos` 数组渲染完整清单，不依赖 result 中的摘要文本

#### 结果展示

与调用展示相同格式（因为 todo_write 的结果就是"同步完成"，关键信息全在参数中）。

如果结果失败：
```
❌ 任务列表更新失败
{错误摘要}
```

### 2. `spawn_task_conversation`（Agent 工具）

**参数结构**：
```json
{
  "title": "子任务标题",
  "goal": "任务目标描述",
  "executor_assistant_name": "助手名",
  "executor_assistant_id": 5
}
```

**结果 content**：`[{"type":"json","json":{"task_conversation_id":123,"task":{"title":"...","status":"pending"},"message":"..."}}]`

#### 调用展示

```
🔀 派发子任务「{title}」→ {executor_assistant_name}
目标：{goal 摘要，截断 120 字符}
```

如果没有 executor 信息，省略 `→` 部分。如果没有 goal，只显示第一行。

#### 结果展示

成功：
```
✅ 子任务已创建「{title}」
执行助手：{executor_name}
状态：{status}
任务 ID：{task_conversation_id}
```

失败：
```
❌ 子任务创建失败「{title}」
{错误摘要}
```

### 3. `load_mcp_server`（Agent 工具）

**参数结构**：`{"name": "搜索关键词"}`

**结果 content**：`[{"type":"json","json":{"servers":[{"server":"名称","summary":"摘要","tools":[{"tool":"工具名","summary":"说明"}]}]}}]`

#### 调用展示

```
🔌 加载工具集：{name}
```

#### 结果展示

成功：
```
🔌 已加载 {n} 个工具集

📦 {server_name}（{tool_count} 个工具：{tool1}、{tool2}、{tool3}）
  {summary}
📦 {server_name_2}（...）
  {summary_2}
```

最多展示 4 个工具集，超出显示"另有 N 个工具集未展开"。每个工具集最多列 3 个工具名。

失败：
```
❌ 未找到匹配的工具集：{错误摘要}
```

```
输出：
{输出摘要}
```

后台命令（content text 包含 "background" 和 "bash_id"）：
```
⚡ 后台命令已启动：{description 或 command}
{content text 摘要}
```

失败：
```
❌ 命令失败：{description 或 command}
{错误输出摘要}
```

## 用户消息格式化规则

用户消息中的附件标签统一做摘要化处理，不泄露正文。

### `fileattachment`

- 图片：`[图片附件] {文件名}`
- 文档：`[文件附件] {文件名}`
- 未知类型：`[附件] {显示名}`

### `skillattachment`

- `[技能附件] {skill_name}`
- `标识符：{identifier}`

不展示 invocation、技能正文、内部提示词。

### 普通 `attachment`

- `[{type}] {显示名}`

## 验收标准

- [ ] 每个工具的调用展示都有自己的图标前缀，不使用统一的"正在执行"包装
- [ ] `todo_write` 展示完整任务清单，每个任务带状态图标（✅⏳⬜🚫）
- [ ] `execute_bash` 展示命令描述，结果展示输出摘要
- [ ] `read_file/write_file/edit_file` 展示文件路径，不展示文件内容
- [ ] `load_mcp_server` 展示工具集列表，不展示原始 JSON
- [ ] `search_web` 展示搜索结果条目标题和 URL
- [ ] `spawn_task_conversation` 展示子任务标题、执行助手、状态
- [ ] 附件标签做摘要化处理，不泄露正文、base64、提示词
- [ ] 兜底 Presenter 对未知工具生成 `🔧 server/tool` 格式
- [ ] 所有工具结果与普通文本在视觉上有明确区分（图标前缀 + 结构化格式）
